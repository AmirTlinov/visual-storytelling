# Работа в проекте

Перед изменениями прочитай [README.md](README.md) о границах библиотеки и [PHILOSOPHY.md](PHILOSOPHY.md) о её визуальном характере.

- Найди владельца поведения; общие исправления делай в библиотеке, предметные — в сцене.
- Используй готовые движки для стандартных задач. Собственный API развивай вокруг проверенных приёмов объяснения.
- Подключай зависимости в общем модуле с фиксированной версией и явной ответственностью.
- Подтверждай новое обобщение различными реальными примерами. Выбирай простую структуру по владельцам; выделяй модуль по конкретной необходимости.
- При замене переведи все поддерживаемые применения и удали заменённый код в том же изменении. Производные артефакты пересобери из исходников.
- Собери законченный срез, затем проведи достаточные проверки затронутых состояний на целевой поверхности.
- Документируй API кратко и рядом с работающим примером; обновляй затронутые превью.
- Фиксируй завершённые изменения conventional commit. Выполняй push при наличии подходящего remote и состояния ветки.

Карта владельцев — в README; публичный API экспортируется из `src/index.ts`, примеры импортируют пакет по имени.
После изменения кода: `npm run check`, `npm run build`, затем проверки затронутых моделей или браузерных сценариев. Браузерные проверки работают с `site/`; сначала пересобери его. Для чистой правки документации проверки исполнения не нужны.

Коллекция `/Users/amir/.codex/skills/visual-explainer` развивается отдельно. Её перенос требует законченного перевода потребителей на пакет и удаления заменённых реализаций; не меняй её попутно с библиотекой.
