# Установка Visual Storytelling

Комплекты для macOS 13.5+ на Apple Silicon и Linux x86_64/ARM64 содержат Node/npm, библиотеку, навык, локальный MCP и готовый пример GPT. Выберите архив с нужными ОС и архитектурой: `linux-x64` — Intel/AMD, `linux-arm64` — ARM. Для первого просмотра дополнительные загрузки не нужны. Требования нативных бинарников записаны в `.plugin-release/release.json`. Linux использует glibc; Alpine/musl в этот профиль не входят.

1. Распакуйте архив. Из его папки выполните:

   ```sh
   ./.plugin-release/runtime/node ./.plugin-release/plugin/install.mjs
   ```

2. Откройте Visual Storytelling в плагинах Codex и запустите настройку. Она проверит подключение и откроет интерактивный пример. Также можно попросить: «Открой пример Visual Storytelling».

Установщик использует CLI текущего приложения из `CODEX_CLI_PATH`, а при запуске из терминала — доступный `codex` в PATH. Он регистрирует плагин, проверяет его MCP-конфигурацию и сохраняет выпуск в `installation/releases` внутри папки приложения, указанной ниже. Codex запускает `sh` из постоянного `PLUGIN_DATA`; `installation/launch` выбирает физическую папку выпуска до запуска Node. После успешной установки распакованный архив можно удалить: исполняемые файлы и рабочая папка процесса не зависят от кэша Codex.

Обновление выполняется той же командой из нового архива. Переподключите плагин в текущем чате: новый MCP запрашивает смену единственного runtime. Текущая очередь завершается на прежнем выпуске (`RUNTIME_UPDATE_PENDING`), затем сохраняются сеансы и запускается выбранная версия. Подключения других чатов не задерживают переключение; их старые MCP сообщают `RUNTIME_UPDATE_REQUIRED` и требуют собственного переподключения. Они не запускают старую версию и не смешивают её интерфейс с новым runtime. После переключения настройка проверяет `story_help` → `story_open`; положение и условия сохранённого сеанса восстанавливаются на паузе. Не удаляйте старые выпуски, пока они используются процессами.

Выпуски до 0.13.0 не умеют освобождать runtime при подключённых старых чатах и могут сообщать `RUNTIME_VERSION_CONFLICT`. Для первого перехода со старого runtime завершите подготовку и закройте его карточки; при оставшемся конфликте настройка требует однократного аккуратного завершения прежнего runtime с сохранением данных. Если плагин запускался из кэша Codex, завершите подготовку до регистрации обновления: Codex удаляет старый кэш.

На Linux папка приложения — `${XDG_DATA_HOME:-$HOME/.local/share}/visual-storytelling`; относительный `XDG_DATA_HOME` игнорируется. Выпуски сохраняются в `installation/releases`, launcher — в `installation/launch`. Проекты по умолчанию находятся в `projects` внутри папки приложения (на Mac — `~/Library/Application Support/Visual Storytelling`); папка новых работ задаётся в настройках. Удаление плагина сохраняет исходники, выпуски и проекты. Обновление установленного плагина сохраняет закреплённую библиотеку каждого проекта. Для её смены попросите «Обнови библиотеку этого проекта».

Первое создание проекта устанавливает закреплённые зависимости через npm registry. Python-генераторы SVG лениво подготавливают интерпретатор и зависимости рисунка. Первое видео отдельно загружает Chromium и FFmpeg для выбранной архитектуры с проверкой SHA-256. На Linux PNG/видео требуют системных библиотек Chromium. На Debian/Ubuntu их можно установить из распакованного комплекта:

   ```sh
   ./.plugin-release/runtime/node ./.plugin-release/node_modules/playwright/cli.js install-deps chromium
   ```

Команда может запросить sudo. Интерактивный пример и автономный HTML этих библиотек не требуют. Higgs использует Apple MLX и в Linux-выпуске недоступен; системные голоса macOS также доступны только на Mac. Тихий авторский путь, Python SVG, HTML/PNG/SVG и MP4 доступны на обеих ОС.

Для разработки: обновите версию `plugin.json`, выполните `npm run plugin:release` и команду установки выше. Проверяйте новый API через `story_help` после переподключения. `--skip-registration` устанавливает runtime без изменения регистрации Codex; вместе с `--directory <path>` задаёт изолированный каталог для проверки, launcher в таком случае запускают с `VISUAL_STORY_INSTALL_DIR=<path>`.

Linux-комплекты собираются на Mac или Linux через Docker: `npm run plugin:linux`. Сборка запускает общий `plugin:release` в закреплённом Linux-образе отдельно для x64 и ARM64 и проверяет установленный MCP, проект и тихий HTML/PNG/MP4. Пример с отдельным Docker context: `npm run plugin:linux -- --context colima-visual-story-linux`. Для одной архитектуры добавьте `--arch x64` или `--arch arm64`. Архивы, SHA-256 и отчёты приёмки сохраняются в `artifacts/plugin/`.

Нативная приёмка описана в `.plugin-release/docs/codex-plugin-tdd.md`. Linux-проверка в контейнере подтверждает runtime, MCP и экспорт; интерфейс плагина в Linux-приложении проверяется отдельно. Ошибки: https://github.com/AmirTlinov/visual-storytelling/issues. Прикладывайте шаги и версию; приватные исходники и логи автоматически не отправляются.
