# Установка Visual Storytelling

Комплект для macOS 13.5+ на Apple Silicon содержит Node/npm, библиотеку, навык, локальный MCP и готовые примеры. Для первого просмотра дополнительные загрузки не нужны. Точный минимум и deployment targets записаны в `.plugin-release/release.json`.

1. Распакуйте архив. Из его папки выполните:

   ```sh
   ./.plugin-release/runtime/node ./.plugin-release/plugin/install.mjs
   ```

2. Откройте Visual Storytelling в плагинах Codex и запустите настройку. Она проверит подключение и откроет интерактивный пример. Также можно попросить: «Открой пример Visual Storytelling».

Установщику нужен доступный `codex` CLI. Он регистрирует плагин, проверяет его MCP-конфигурацию и сохраняет выпуск в `~/Library/Application Support/Visual Storytelling/installation/releases`. Codex запускает `sh` из постоянного `PLUGIN_DATA`; `installation/launch` выбирает физическую папку выпуска до запуска Node. После успешной установки распакованный архив можно удалить: исполняемые файлы и рабочая папка процесса не зависят от кэша Codex.

Обновление выполняется той же командой из нового архива. Файлы существующего выпуска сохраняются, работающая подготовка завершается на своей версии. Затем закройте карточки Visual Storytelling и переподключите плагин. Конфликт активной и новой версии сообщает `RUNTIME_VERSION_CONFLICT`; второго владельца сессий при этом не создаётся. После переподключения настройка снова проверяет `story_help` → `story_open`. Не удаляйте старые выпуски, пока они используются процессами. Перед первым переходом со старого плагина, который запускался из кэша Codex, завершите текущую подготовку: Codex удаляет старый кэш при регистрации обновления.

Проекты по умолчанию находятся в `~/Library/Application Support/Visual Storytelling/projects`; папка новых работ задаётся в настройках. Удаление плагина сохраняет исходники, выпуски и проекты. Обновление установленного плагина сохраняет закреплённую библиотеку каждого проекта. Для её смены попросите «Обнови библиотеку этого проекта».

Первое создание проекта устанавливает закреплённые зависимости через npm registry. Первое видео отдельно загружает Chromium и FFmpeg с проверкой SHA-256. Озвучка по запросу подготавливает локальную Python-среду и модели; системный голос macOS выбирается явно. Без голоса доступен весь авторский путь.

Для разработки: обновите версию `plugin.json`, выполните `npm run plugin:release` и команду установки выше. Проверяйте новый API через `story_help` после переподключения. `--skip-registration` устанавливает runtime без изменения регистрации Codex; вместе с `--directory <path>` задаёт изолированный каталог для проверки, launcher в таком случае запускают с `VISUAL_STORY_INSTALL_DIR=<path>`.

Нативная приёмка описана в `.plugin-release/docs/codex-plugin-tdd.md`. Ошибки: https://github.com/AmirTlinov/visual-storytelling/issues. Прикладывайте шаги и версию; приватные исходники и логи автоматически не отправляются.
