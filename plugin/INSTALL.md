# Установка Visual Storytelling

Текущий комплект для macOS 13.5+ Apple Silicon содержит Node/npm, библиотеку, навык, локальный MCP и каталог примеров. Для первого просмотра дополнительные загрузки не нужны. Требования нативных бинарников записаны в `.plugin-release/release.json`. Windows и Linux отложены и в приёмку этого выпуска не входят.

1. Распакуйте архив. Из его папки выполните:

   ```sh
   ./.plugin-release/runtime/node ./.plugin-release/plugin/install.mjs
   ```

2. Откройте Visual Storytelling в плагинах Codex и запустите настройку. Она проверит подключение и откроет интерактивный пример. Также можно попросить: «Открой пример Visual Storytelling».

Установщик использует CLI текущего приложения из `CODEX_CLI_PATH`, а при запуске из терминала — доступный `codex` в PATH. Он регистрирует плагин, проверяет его MCP-конфигурацию и сохраняет выпуск в `installation/releases` внутри папки приложения, указанной ниже. Codex запускает `sh` из постоянного `PLUGIN_DATA`; `installation/launch` выбирает физическую папку выпуска до запуска Node. После успешной установки распакованный архив можно удалить: исполняемые файлы и рабочая папка процесса не зависят от кэша Codex.

Обновление выполняется той же командой из нового архива. Переподключите плагин в текущем чате: новый MCP запрашивает смену единственного runtime. Текущая очередь завершается на прежнем выпуске (`RUNTIME_UPDATE_PENDING`), затем сохраняются сеансы и запускается выбранная версия. Подключения других чатов не задерживают переключение; их старые MCP сообщают `RUNTIME_UPDATE_REQUIRED` и требуют собственного переподключения. Они не запускают старую версию и не смешивают её интерфейс с новым runtime. После переключения настройка проверяет `story_help` → `story_open`; положение и условия сохранённого сеанса восстанавливаются на паузе. Не удаляйте старые выпуски, пока они используются процессами или закреплены в проектах.

Выпуски до 0.13.0 не умеют освобождать runtime при подключённых старых чатах и могут сообщать `RUNTIME_VERSION_CONFLICT`. Для первого перехода со старого runtime завершите подготовку и закройте его карточки; при оставшемся конфликте настройка требует однократного аккуратного завершения прежнего runtime с сохранением данных. Если плагин запускался из кэша Codex, завершите подготовку до регистрации обновления: Codex удаляет старый кэш.

Папка приложения — `~/Library/Application Support/Visual Storytelling`. Выпуски сохраняются в `installation/releases`, launcher — в `installation/launch`. Проекты по умолчанию находятся в `projects`; папка новых работ задаётся в настройках. Удаление плагина сохраняет исходники, выпуски и проекты. Обновление установленного плагина сохраняет закреплённую библиотеку каждого проекта. Для её смены попросите «Обнови библиотеку этого проекта».

`story_create` с [компактным `document`](../skills/visual-explainer/references/live-explanation.md) использует заранее собранный приём. Проект сразу сохраняет pin на точный физический выпуск в `scene-runtime.json`; первый живой показ не запускает npm, сборку страницы или упаковку runtime. Валидный частичный ввод может открыться как предварительный кадр до результата создания. Обновление плагина не меняет этот pin; недоступный закреплённый выпуск требует восстановления или явного обновления проекта. Переносимый архив с точной библиотекой создаётся при выпуске исходников.

Проект с собственным JS/TS и дополнительные зависимости используют обычную установку через npm registry и сборку. Python-генераторы SVG лениво подготавливают интерпретатор и зависимости рисунка. Первое видео отдельно загружает Chromium и FFmpeg с проверкой SHA-256.

Озвучка опциональна. По умолчанию используется локальный Higgs TTS 3 BF16 на Apple MLX. Агент может подключить выбранную пользователем локальную модель или API по [контракту адаптера](../skills/visual-explainer/references/voice-adapter.md); требования определяет выбранная модель. Системных голосов и автоматической замены провайдера нет.

Для разработки: обновите версию `plugin.json`, выполните `npm run plugin:release` и команду установки выше. Проверяйте новый API через `story_help` после переподключения. `--skip-registration` устанавливает runtime без изменения регистрации Codex; вместе с `--directory <path>` задаёт изолированный каталог для проверки, launcher в таком случае запускают с `VISUAL_STORY_INSTALL_DIR=<path>`.

Нативная приёмка описана в `.plugin-release/docs/codex-plugin-tdd.md`. Ошибки: https://github.com/AmirTlinov/visual-storytelling/issues. Прикладывайте шаги и версию; приватные исходники и логи автоматически не отправляются.
