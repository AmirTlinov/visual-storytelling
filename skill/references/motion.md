## Оформление

- Эталон коллекции — «Остаток» и «4 × 5»: тонкое рисованное письмо,
  спокойные контуры и единая тетрадная сетка на прозрачной поверхности.
  `ink.css` задаёт этот стиль всем форматам; один контейнер владеет сеткой,
  а её шаг и начало совпадают с измеряемой геометрией.
  Статические подписи используют `pencil.woff2`, собранный из штрихов `src/ink/glyphs.ts`,
  поэтому заголовки, формулы, управление и письмо по ходу речи выглядят согласованно.
  Выбери 2–3 смысловых акцента и сохраняй цвет роли между предметом, подписью,
  действием и формулой; синий, оранжевый, фиолетовый и зелёный доступны равноправно.
  Тонкие линии и буквы непрозрачны и контрастны в обеих темах; мягкая заливка
  берёт цвет своего предмета, а прозрачность остаётся у заливок и сетки.
- Ручная работа проявляется в малой устойчивой неровности контура и аккуратном заполнении; координаты модели, буквы и числа сохраняют точность.
  Ячейки, выбранные токены и обычные заливки имеют чёткий слегка неровный край; размытие всей фигуры создаёт грязь.
  Для явно маркерного штриха используй `SketchInk.markerDefs` / `markerMarkup` из `SketchInk` из пакета: мягкость ограничена короткими окончаниями, центр сохраняет чистый цвет, подписи рисуются отдельно.
- Подписи пиши прямо на листе. Тучки не использовать. Геометрия остаётся устойчивой.
- Предметы занимают основное место. Голос объясняет смысл; на листе — короткая опора.
  Оставляй паузу для счёта, сравнения или предсказания следующего шага.
- Управление продолжает рисунок: тонкие графитовые контуры, рукописные подписи,
  подчёркнутый выбор и одна строка плеера — воспроизведение, шкала, время, звук.
  Значки имеют доступные имена; текст управления не выделяется, клик не оставляет
  рамку, клавиатурный фокус отмечен карандашом.
- Рисуй детали, участвующие в действии. Для готовых иконок сохраняй источник и лицензию.

Цветовые переменные, масштаб сетки и измерение подписей описаны в
[сборке сцены](scene-authoring.md); они применяются и к готовому рисунку на паузе.

## Движение и звук

Для слияния текста и фигур используй `InkFusion` из пакета, [пример и API](../../examples/ink-fusion/README.md).
Передай исходные формы, результат и позы. Начинай `morph` уже при сближении: штрихи
сразу направляются в конечные буквы, а линии с общим назначением соединяются по пути.
Промежуточная бесформенная масса не нужна. Контактные перемычки рассчитывает движок;
почерк берётся из `SketchPencil`. Переходы конкретных букв вручную не задавай.
Для упругости подключай `Physics2D.fusion` из `./physics/2d`: она деформирует
те же штрихи через Rapier и принимает время общего таймлайна. `frame(time)` задаёт
повторяемую траекторию, `setShapes` сбрасывает физическую историю после её изменения.
Для предложений и абзацев передавай текст целиком в `InkFusion.text` с `maxWidth`
и `align: 'left'`: движок сохраняет слова, переносы и размер шрифта. При изменении
ширины пересоздай текст и обнови поверхность через `setSize`; высоту бери из `bounds`.

Перо ведёт по буквам и контурам; стрелка идёт к адресату и завершается наконечником.
Письмо, действия и слова связывай по [аудиометкам](narration.md#метки-и-js).
Для рассказа без звука используй один управляемый таймлайн с теми же смысловыми шагами.

## Проверка

Примени [проверки формата](../SKILL.md#сделать-и-проверить) на целевой поверхности.
Без звука в ключевом переходе должны быть видны объект, действие и результат.
Проверку понятности для новичка проводи с таким зрителем.

Для движения выбери нужный источник и открой полученный `motion.png`:

Из установленного навыка: сначала `cd` в каталог `SKILL.md`, затем
`node ../tools/scene.mjs review /absolute/input --motion --out /absolute/report`.
Примеры ниже запускаются из корня библиотеки.

```sh
# Из каталога библиотеки; установленный пакет предоставляет visual-story.
node tools/scene.mjs review site/explorer-svg --motion --cue move_x --out artifacts/motion
node tools/scene.mjs review story.html --motion --from .8 --frames 16 --out artifacts/motion
node tools/scene.mjs review recording.mp4 --motion --from 1.2 --frames 16 --out artifacts/motion
node tools/scene.mjs review frames.json --motion --out artifacts/motion
```

| Источник | Выбор времени |
| --- | --- |
| Сцена библиотеки: каталог, HTML или SVG с управляемым таймлайном | `--cue ID` берёт короткое окно в середине метки; `--from` задаёт начало явно. `--fps 60` задаёт шаг времени модели. |
| Запись интерфейса, анимации или ролик | `--from` в секундах исходной шкалы PTS; FFmpeg сохраняет кадры, повторы и интервалы. |
| Отрисованные кадры, в том числе imagegen | PNG и manifest с временами в порядке захвата; `--from` выбирает первое время не раньше указанного. |

`frames.json`: `{"frames":[{"file":"01.png","time":0},{"file":"02.png","time":0.017}]}`.
Пути относительны manifest, времена строго возрастают. `--frames` выбирает 2–32 кадра;
по умолчанию 12. Это локальное окно: при 60 fps оно охватывает 0,183 с.
Для выбора перехода целиком обычный `review --cue ID` строит обзор его состояний;
затем `--motion` показывает соседние кадры внутри действия.

Один лист содержит цветные контуры, максимальную межкадровую разность, долю
изменившихся пикселей, интервалы и последовательность в общей приближенной области.
Контекст показан отдельно. Прозрачность учитывается в цветах и альфа-канале;
кадры разного размера сохраняют общий масштаб и привязку к левому верхнему углу.
`index.html` автономен, `motion.json` хранит числа. Ответ команды сразу сообщает
окно, масштаб, повторы, подсказку области и затраченное время.

Быстрый обзор ограничен 960 px по длинной стороне. Для тонких штрихов, слабого
мерцания или сдвигов на пиксель повтори с `--crop x,y,w,h --max-size 0`:
координаты задаются в исходных пикселях, готовая область есть в `suggestedCrop`.
`--threshold 8` подавляет слабые различия; уменьши его для малоконтрастных деталей.
Если изменений не видно, проверь окно, масштаб и порог перед выводом.

Сверь следы с замыслом: разгон, сохранность формы, дрожание, паузы, мерцание.
Процент изменений зависит также от цвета, площади и камеры; скорость объекта
по нему не определяется. Для стыка петли запиши конец и начало следующего оборота
одним непрерывным фрагментом. Монтажные склейки рассматривай отдельно.
Перемотка сцены проверяет геометрию по времени модели; ритм живого интерфейса
проверяй записью реального взаимодействия на целевом устройстве, учитывая
частоту и пропуски записи. Для CSS/Canvas/SMIL без управляемого таймлайна,
чужой страницы или нативного приложения используй запись либо PNG с временами.

Для отчёта нужны зависимости пакета и Chromium (`npx playwright install chromium`);
для видео также нужен FFmpeg в PATH. Долгий ролик декодируется от ближайшей
опорной точки выбранного окна. Алгоритм — пороговые дельты RGBA и цветные контуры;
для спорной траектории добавляй отслеживание опорных точек/optical flow адресно.
