## Оформление

- Эталон коллекции — «Остаток» и «4 × 5»: тонкое рисованное письмо,
  спокойные контуры и единая тетрадная сетка на прозрачной поверхности.
  `ink.css` задаёт этот стиль всем форматам; один контейнер владеет сеткой,
  а её шаг и начало совпадают с измеряемой геометрией.
  Статические подписи используют `pencil.woff2`, собранный из штрихов `src/ink/glyphs.ts`,
  поэтому заголовки, формулы, управление и письмо по ходу речи выглядят согласованно.
  Выбери 2–3 смысловых акцента и сохраняй цвет роли между предметом, подписью,
  действием и формулой; синий, оранжевый, фиолетовый и зелёный доступны равноправно.
  Тонкие линии и буквы непрозрачны и контрастны в обеих темах; мягкая заливка
  берёт цвет своего предмета, а прозрачность остаётся у заливок и сетки.
- Ручная работа проявляется в малой устойчивой неровности контура и аккуратном заполнении; координаты модели, буквы и числа сохраняют точность.
  Ячейки, выбранные токены и обычные заливки имеют чёткий слегка неровный край; размытие всей фигуры создаёт грязь.
  Для явно маркерного штриха используй `SketchInk.markerDefs` / `markerMarkup` из `SketchInk` из пакета: мягкость ограничена короткими окончаниями, центр сохраняет чистый цвет, подписи рисуются отдельно.
- Подписи пиши прямо на листе. Тучки не использовать. Геометрия остаётся устойчивой.
- Предметы занимают основное место. Голос объясняет смысл; на листе — короткая опора.
  Оставляй паузу для счёта, сравнения или предсказания следующего шага.
- Управление продолжает рисунок: тонкие графитовые контуры, рукописные подписи,
  подчёркнутый выбор и одна строка плеера — воспроизведение, шкала, время, звук.
  Значки имеют доступные имена; текст управления не выделяется, клик не оставляет
  рамку, клавиатурный фокус отмечен карандашом.
- Рисуй детали, участвующие в действии. Для готовых иконок сохраняй источник и лицензию.

Цветовые переменные, масштаб сетки и измерение подписей описаны в
[сборке сцены](scene-authoring.md); они применяются и к готовому рисунку на паузе.

## Движение и звук

Для слияния текста и фигур используй `InkFusion` из пакета, [пример и API](../../examples/ink-fusion/README.md).
Передай исходные формы, результат и позы. Начинай `morph` уже при сближении: штрихи
сразу направляются в конечные буквы, а линии с общим назначением соединяются по пути.
Промежуточная бесформенная масса не нужна. Контактные перемычки рассчитывает движок;
почерк берётся из `SketchPencil`. Переходы конкретных букв вручную не задавай.
Для упругости подключай `Physics2D.fusion` из `./physics/2d`: она деформирует
те же штрихи через Rapier и принимает время общего таймлайна. `frame(time)` задаёт
повторяемую траекторию, `setShapes` сбрасывает физическую историю после её изменения.
Для предложений и абзацев передавай текст целиком в `InkFusion.text` с `maxWidth`
и `align: 'left'`: движок сохраняет слова, переносы и размер шрифта. При изменении
ширины пересоздай текст и обнови поверхность через `setSize`; высоту бери из `bounds`.

Перо ведёт по буквам и контурам; стрелка идёт к адресату и завершается наконечником.
Письмо, действия и слова связывай по [аудиометкам](narration.md#метки-и-js).
Для рассказа без звука используй один управляемый таймлайн с теми же смысловыми шагами.

## Проверка

Проверь затронутый переход наложением соседних кадров, разностями и временными
метками; открой возвращённый `motion.png` через `view_image` и сопоставь результат
с ожидаемым действием. Для живого интерфейса запиши реальное взаимодействие,
включая характерные повторные действия; глубину проверки выбирай по изменению.

Из установленного навыка сначала перейди через `cd` в каталог `SKILL.md`, затем
вызывай `node ../tools/scene.mjs` с абсолютными путями входа и отчёта. Из корня
библиотеки работает `node tools/scene.mjs`, из установленного пакета — `npx visual-story`.
Зависимости проверяет `review --doctor`; все параметры — `review --help`.
При недоступном localhost или Chromium анализируй сохранённые PNG/видео: HTML, JSON и кадры `analysis/*.png` сохраняются, а отсутствие PNG-обложек отмечается `previews.available: false`.

```sh
# Обычный сайт: библиотека и собственный таймлайн на странице не требуются.
node tools/scene.mjs review http://localhost:3000 --click '#open' --target '#panel'
# HTML/CSS/JS, Canvas, SVG, WebGL: захват настоящего исполнения.
node tools/scene.mjs review /absolute/page.html --capture --click '#start' --seconds 2
# Повторные действия, клавиатура, drag, scroll: один воспроизводимый сценарий.
node tools/scene.mjs review http://localhost:3000 --scenario /absolute/flow.json
# Повтор после исправления и сопоставление с прошлым отчётом.
node tools/scene.mjs review /absolute/BEFORE/replay.json --motion --baseline /absolute/BEFORE --out /absolute/AFTER
# Повторный анализ сохранённой записи без запуска сайта.
node tools/scene.mjs review /absolute/REPORT/capture/frames.json --motion --from .3
# Нативное окно macOS: сначала список, затем запись выбранного ID.
node tools/scene.mjs review --windows
node tools/scene.mjs review --window 123 --seconds 3
# Видео: PTS сохраняются. --seconds сканирует интервал и выбирает подробный участок.
node tools/scene.mjs review recording.mp4 --motion --from 1.2 --seconds 3
# Кимограмма через деталь: горизонтальная полоса y=260, толщина 5 исходных px.
node tools/scene.mjs review recording.mp4 --motion --seconds 3 --crop 0,200,800,200 --slice x,260,5
# Сцена библиотеки: управляемое время модели и соседние состояния.
node tools/scene.mjs review site/explorer-svg --motion --cue move_x
```

`--out` по умолчанию создаёт свежий каталог `artifacts/motion-*`. Ответ команды —
JSON с абсолютными путями, окном, масштабом, наблюдениями и временем выполнения.
Начни с `image` (`motion.png`) и `focus`: краткий обзор показывает до трёх групп
наблюдений, выбранное окно, контекст и наложение. Это указатели для проверки;
отсутствие автосигналов само по себе не оценивает качество движения.
`framesImage` (`frames.png`) содержит все выбранные кадры, дельты и интервалы;
`photometryImage` — яркость, цвет и кимограмму. В HTML ссылки из наблюдений раскрывают
нужный раздел; полный список, сравнение и условия измерений сохранены. Плеер позволяет
проиграть кадры и перемотать их. Нажатие на время события открывает ближайшую метку записи;
плеер показывает фактический кадр, шаг назад/вперёд и ввод времени. Для DOM сохраняется
пометка о неподтверждённой синхронизации. Если браузер принимает только HTTP, запусти возвращённую команду `preview`
и открой её localhost URL. Храни каталог отчёта целиком: `capture/` содержит исходные кадры, `analysis/` —
выбранные, `motion.json` — числа, `telemetry.json` — наблюдения браузера.

`photometry.png` отдельно собирает яркость, RGB, насыщенность среднего цвета,
альфа-канал, карту 12 областей во времени и кимограмму; тот же раздел есть в HTML.
`--crop` ограничивает все эти измерения. Полоса кимограммы выбирается по изменениям
яркости; `--slice x,Y,толщина` или `y,X,толщина` задаёт её в исходных координатах.
Время по горизонтали линейно, пропуски отмечены фиолетовой штриховкой; цвет карты показывает отклонение
яркости области от первого кадра. Движение объекта через фиксированную область
тоже меняет её цвет: сверяй графики с кимограммой и кадрами, для цвета самого
движущегося объекта нужна запись с совмещённым объектом.
Координата `--slice` выбирает пиксель; отчёт показывает геометрический центр полосы
(при исходном масштабе индекс 125 соответствует центру 125,5 px).

Спектрограмма появляется при повторяющихся изменениях, минимум 64 кадрах и секунде
почти равномерной записи (отклонения интервалов ≤2%). Редкий CDP-захват и пропуски
дают явную причину пропуска спектра. Видео или PNG-манифест с `--seconds N` анализируется
на всём выбранном интервале; окно из 12 кадров остаётся подробным фрагментом.
Частотный шаг указан рядом: STFT с окном Hann и удалением линейного тренда показывает
периодичность области, включая движение. Яркость считается в linear sRGB с альфа
на белом фоне, для тёмной темы — на чёрном; RGB и HSV-насыщенность относятся к среднему цвету.
Методы: [кимограмма ImageJ](https://imagej.net/plugins/trackmate/extensions/trackmate-kymograph),
[STFT SciPy](https://docs.scipy.org/doc/scipy/tutorial/signal.html#short-time-fourier-transform).

Пример `flow.json` (URL можно задать здесь; локальные пути относительны этому файлу):

```json
{"actions":[{"type":"click","selector":"#open"},{"type":"wait","ms":120},
 {"type":"click","selector":"#close"}],"targets":["#panel"],"seconds":2}
```

Явный адрес в команде имеет приоритет над `url` сценария: один flow можно проверить
на другой версии сайта.

Действия: `click`, `dblclick`, `hover`, `fill` (`value` либо имя переменной окружения
в `env`), `press` (`key`), `scroll` (`x`/`y`), `drag` (`selector`/`to`), `wait` (`ms`).
Элемент выбирается через `selector` либо `role` + `name`. `targets` — CSS-селекторы;
элементы могут появиться после действия. `seconds` — время после последнего действия.
Для быстрых повторных нажатий в одну точку используй
`{"type":"click","selector":"#toggle","repeat":2,"intervalMs":120}`:
готовность проверяется один раз, затем отправляется ввод по расписанию.
Фактические интервалы click выводятся в ответе и отчёте; занятость приложения
может задержать обработку. `wait 120` означает паузу между завершёнными шагами,
к которой добавляется ожидание готовности следующего элемента.
Сценарий сохраняется в `replay.json`; значения `fill.value` попадают в этот файл,
для секретов используй `env`. Ошибка действия сохраняет частичный отчёт и даёт код 2.

Для уже открытого авторизованного Chromium используй URL и `--cdp ENDPOINT`:
команда выберет существующую вкладку с точно совпадающим URL, сохранит её настройки
и отключится после захвата. Действия выполняются на настоящей вкладке.
Новые вкладки поддерживают `--width`, `--height`, `--theme dark`, `--reduced`,
`--ready SELECTOR` и `--headed`. Выбирай проверки под затронутые состояния.

В браузере отдельно видны траектория DOM-элемента и скорость его центра,
краткие исчезновения, выход за viewport, обрезание содержимого, события фокуса,
layout shifts, ошибки страницы, Event Timing и длительные кадры основного потока
с источниками скриптов. Поддержка API указана в JSON. Эти наблюдения помогают
найти момент и причину; оценка графика учитывает задуманный разгон и торможение.
CDP отправляет изображения при обновлениях: интервалы захвата не равны FPS дисплея.
Синхронизация изображения и DOM не установлена; погрешность времени показа
пикселей неизвестна и отмечена как `null`, скорость по этим интервалам не вычисляется.
Event Timing относится к измеренным дискретным взаимодействиям, а rAF — к основному
потоку. Захват и чтение геометрии тоже добавляют нагрузку; сравнивай одинаковые условия.

Для маленьких деталей повтори анализ сохранённых кадров с
`--crop x,y,w,h --max-size 0`; координаты — в исходных пикселях. По умолчанию длинная
сторона анализа ограничена 960 px. `--threshold 8` подавляет слабые различия;
уменьши порог для малоконтрастных деталей. `suggestedCrop` даёт готовую область.
`--from` и `--frames 12` (2–32) выбирают подробное окно. Длинная запись сохраняется
целиком в пределах 600 снимков; превышение отражается в отчёте. Сценарий ограничен
40 действиями и 45 секундами, `--seconds` — 0.1–15 секунд.

`--baseline REPORT` сопоставляет начало, середину и конец относительно
соответствующего фактического клика, показывает разность, расстояние меток
захвата и расхождение интервалов ввода. `--loop` сравнивает
первое и последнее состояния; для скорости на стыке запиши два оборота непрерывно.
Пиксельные изменения зависят от цвета, площади, камеры и монтажа. Прозрачность
учитывается; автоматические сигналы обозначают участки для просмотра.

Для готовых кадров: `frames.json` содержит
`{"frames":[{"file":"01.png","time":0},{"file":"02.png","time":0.017}]}`;
пути относительны manifest, времена строго возрастают. Для сцены библиотеки
`--cue ID` выбирает середину метки, `--fps 60` — шаг времени модели.
Для обычного видео `--from/--frames` берёт короткое окно без обзора всей записи.
FFmpeg сохраняет порядок, повторы и исходные временные метки.

Нужны зависимости пакета и Chromium; видео и нативная запись используют FFmpeg.
Прямой захват окна использует macOS 15+, Xcode Command Line Tools и уже выданное
разрешение Screen Recording. На других системах подай видео или PNG с временами.
Функции приложения, доступность и соответствие замыслу проверяй подходящим
сценарием на целевой поверхности; отчёт помогает рассмотреть его движение.
