# Проверка авторского пути: MLP · 4 октября 2026

Короткий запрос отдельному агенту — «Объясни, как работает MLP, в виде понятного
интерактивного визуального рассказа» — дал рабочий рассказ 3:29: XOR → взвешивание
→ сумма → ReLU → сеть → изменение одного веса. Он выявил конкретные разрывы между
операциями и лишнюю ручную работу. После исправления владельцев тот же рассказ
пересобран из установленного пакета через публичный API.

## Что теперь принадлежит библиотеке

| Владелец                        | Исправление и удалённая ручная работа                                                                                                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `morph/field`                   | Общая регистрация исходного и конечного объёма сохраняет прямые грани при изменении размеров. Каждая пара обрабатывает контакт независимо; CPU и GPU используют те же группы. Глобальный путь ограничения граней удалён.                                                  |
| `morph/ink`                     | Надпись и измерительная сетка следуют тому же переносу материала, что и тело. Текст завершает сборку в конечном положении без последующего сдвига якоря.                                                                                                                  |
| `MathMorph.chain`               | Результат становится тем же телом на входе следующего шага: сохраняются идентификатор, происхождение, размер и положение. `dot → add → apply` заменяет отдельные постановки суммы и активации.                                                                            |
| `morph/timing`                  | `render(frame, cues)` связывает операцию с рассказом. Общая политика reduced motion оставляет опорные состояния и сохраняет момент раскрытия результата. Сцены больше не выбирают собственный порог или промежуточную позу.                                               |
| `morph/layout`                  | Пары переносятся по доступной ширине, надписи остаются читаемыми, высота композиции следует содержимому. 2D и 3D используют одну раскладку. Из MLP удалены `foreignObject` и ручной пересчёт арифметики.                                                                  |
| `ink/lettering`, `recipes/node` | Измеряются фактические штрихи; текст центрируется внутри прямоугольника или эллипса с отступом. Узел при необходимости растёт, сохраняя минимальный размер текста. Из MLP удалены ручные `maxWidth`, размер шрифта по длине числа и положение базовой линии внутри круга. |
| `SvgLayout.along`               | Подпись размещается по измеренной геометрии с учётом узлов, соседних надписей и пересекающих связей. Невидимый кончик пера и скрытый шрифтовой образец исключены из измеряемых границ.                                                                                    |
| `story`, `SceneShell`           | `derive(values, frame)` даёт один вычисленный кадр для рассказа, исследования и snapshot. Оболочка повторяет кадр после resize; локальный дублирующий обработчик удалён.                                                                                                  |
| `visual-story api`              | Один запрос раскрывает сигнатуру, связанные типы и публичные импорты из установленного пакета; внутренние несвязанные функции не выводятся.                                                                                                                               |

Предметная модель MLP, выбор учебных примеров, реплики и устройство сети остаются
ответственностью автора. Учебный шаг изменяет одну связь; это не имитация обучения
всех параметров сети.

## Проверка поведения

- Новый потребитель использует установленный архив пакета, без внутренних импортов.
- Проверены одинаковые тела между шагами, обратная перемотка, знаковая функция,
  раскрытие результатов в обычном и reduced motion, перенос пар при узкой ширине.
- Реальный браузер проверяет полные штрихи и центр надписей, включая `0,858`, смену
  чисел в скрытом узле, восстановление после seek, рост длинной подписи и отсутствие
  повторных DOM-изменений при неизменном значении. Связи следуют границам тела.
- Сопоставлены 2D-арифметика MLP и принятый `written-morph`; дополнительно проверена
  3D-арифметика при ширине 375 px. Узкий экран проверяется через viewport браузера.
- Независимый разбор закрыл взаимное влияние соседних пар, обрезание анизотропных
  форм, скачки сетки материала и лишнее обновление контура из-за численной погрешности.

В предыдущем проходе отдельно проверены ввод и предметная модель: три шага обучения
дали `w: 0.2 → 0.6625`, ошибку `0.32 → 0.056953125`; возвращение к рассказу восстановило
его параметры. Тогда же исправлены проверка актуальности локальной озвучки и
нормализация цветового профиля в диагностике движения.

Короткий браузерный прогон MLP на 375 px: 240 кадров обновления, медиана CPU 3,6 мс,
p95 4,3 мс; интервал отображения p95 20,8 мс на текущем компьютере. Шесть быстрых
учебных шагов дали `w = 0,8576171875`; показанное `0,858` осталось внутри окружности.
