# Согласованный морфинг

Автор задаёт операцию, объекты и метки времени рассказа. Размещение, сближение, контакт, перенос штрихов и читаемость принадлежат движку. Рабочий образец — [«Форма несёт смысл»](../examples/written-morph/scene.js): числа, слова на телах, разделение и абзацы, с переключением 2D/3D.

Объёмный морф поддерживает бруски, шары и капсулы; `Morph2D` показывает срез тех же тел. Произвольные 2D-силуэты задаются через `InkFusion.shape` и `InkMorph`. Импортированные 3D-сетки пока не входят в этот API.

```js
import { Morph, Morph2D, InkMorph } from '@visual-storytelling/core';
import { Morph3D } from '@visual-storytelling/core/three';

const operation = Morph.merge(
  [Morph.box([1.15, 1.15, 0.97], 'Свет'), Morph.sphere(0.575, 'Тень')],
  Morph.capsule(0.62, 2.6, 'Объём'),
);
const body = Morph3D.mount(view, operation);
view.setObject(body.object, { fitView: false });
body.render(frame, 'merge');
view.shot({ target: body.bounds, direction: [-3.5, 2.2, 9] });

// Та же операция в плоском рисунке.
const flat = Morph2D.mount(stage, operation, { id: 'meaning' });
flat.render(progress);

// Слова, предложения, абзацы или маски InkFusion.shape без тела.
const words = await InkMorph.mount(stage, {
  sources: ['Свет', 'Тень'],
  targets: ['Объём'],
});
words.render(progress);
```

`Morph.transform(from, to)`, `merge(parts, whole)` и `split(whole, parts)` сохраняют резкие грани до контакта и направляют общую поверхность к результату. Сближение сохраняет исходные тела до физического касания; разделение удерживает уже существующие связи до разрыва. Размеры `box([w,h,d], text?)`, `sphere(radius, text?)`, `capsule(radius, length, text?)` задают внешние границы; длина капсулы включает концы. `text` принимает строку или число, `grid` у объекта — шаг измерительных линий.

При разделении обращённые друг к другу грани стягиваются в перешейки, затем расходятся. Части округлого целого сохраняют его округлость до разрыва; окончательные грани появляются после отделения. Тонкие тела сужаются по обеим поперечным осям. Упругость рассчитывается по скорости касания, изменению формы и площади соединённого перешейка. Одна затухающая пружинная модель обслуживает все формы; длительность берётся из метки рассказа. Тело и надпись движутся вместе, дополнительная деформация сохраняет объём. Перемотка воспроизводит тот же кадр, reduced motion пропускает упругий отклик. Для короткого действия без озвучки образец отводит 3,4 секунды и отдельные паузы на чтение; в рассказе длительность задаёт метка речи.

Надписи и сетка входят в материал общей поверхности: штрихи следуют текущей форме, перспективе и её глубине, скрываются телом при вращении. Письмо занимает переднюю поверхность; обратная сторона остаётся чистой. 2D показывает срез того же поля, тот же перенос чернил и фильтр мелких фрагментов. SVG-экспорт сохраняет GPU-чернила встроенным изображением вместе с векторным контуром.

Надпись переносится целыми словами по пропорциям исходного тела, числа остаются цельными. Эта компоновка сохраняется при деформации и перемотке. Измерительная сетка привязана к материалу: растяжение переносит существующие линии, сохраняя их количество.

`InkMorph` измеряет видимые штрихи и размещает слова рядами, а абзацы переносит по ширине контейнера. Маски вписываются с сохранением пропорций и без пустых полей. Высота следует содержимому, включая обычный HTML-контейнер вне `SceneShell`; ручная высота и отдельное мобильное масштабирование не нужны. Компонент ведёт штрихи прямо к результату и добавляет упругость Rapier. Длительность берётся из метки рассказа; смена длительности пересчитывает физический трек, сохраняя сопоставление штрихов. Буквы, слова и абзацы используют один алгоритм: исходные штрихи собирают разные участки конечного контура, их стыки плавно сходятся. Короткие исходные штрихи сохраняются; фильтр мелких фрагментов применяется к растущим новым деталям. У компонент нет собственных часов: `render(progress)` принимает 0…1 и поддерживает произвольную перемотку. `setOperation` заменяет входы и возвращает переход к началу, изменение ширины сохраняет текущий кадр. `dispose` освобождает ресурсы; 3D-компонент также освобождается вместе с viewport. Скрытые представления дорисовывают последний кадр при показе. Один экземпляр переиспользуется между главами.

## Записать результат в ячейку

`MathMorph3D` ведёт вычисление и последующую доставку по двум меткам рассказа:

```js
const calculation = MathMorph3D.mount(view, MathMorph.dot(inputs, weights), {
  id: 'projection',
  delivery: { to: outputCell },
});
calculation.render(frame, 'calculate', 'place');
```

`outputCell` — будущий результат, `Object3D` в той же сцене. Его собственная
геометрия задаёт размер и адрес; для составного рисунка или логического якоря
можно передать `bounds: Box3` в локальных координатах ячейки. Текст и значение
получателя задаёт предметная модель. Библиотека переносит тело вместе с числом
и семантическими якорями, учитывает вложенные масштабы и повороты. `via: [x,y,z]`
задаёт необязательную точку изгиба пути в мировых координатах.

Метка `place` начинается после завершения последнего этапа вычисления.
Появлением получателя владеет доставка: до прибытия он скрыт, при прибытии
заменяет вычисленное тело. Обратная перемотка восстанавливает оба состояния;
`setOperation` возвращает действие к началу, `dispose` освобождает получателя
и восстанавливает его исходную видимость. Каждый получатель имеет одного владельца.
Не добавляй к нему отдельный `reveal` или переключение `visible`.
Reduced motion сохраняет готовое число на месте расчёта до окончания метки доставки.

Для ручного исследования доступны `render(calculationProgress, undefined, deliveryProgress)`
или тот же `cueSheet.at(seconds)`. Для последовательной записи в несколько ячеек
перед кадром вызови `calculation.setDelivery({ to: cells[index], via })`; экземпляр
вычисления и поверхности сохраняется. Освобождённая ячейка сохраняет последнее
состояние, а сцена задаёт видимость предыдущих адресов при перемотке.
`setDelivery()` освобождает текущий адрес и возвращает поверхность к месту расчёта.
Доставка включает сценическое размещение;
собственной камеры и часов у неё нет. Родительские группы можно свободно
перемещать; transform поверхности результата принадлежит доставке. Нулевой масштаб
и переход между противоположными зеркальными ориентациями отклоняются:
непрерывный перенос не должен схлопывать тело.
Рабочая основа [«Куда попадает результат?»](../examples/result-delivery/scene.js)
показывает сумму в памяти и скалярное произведение в векторе.

## Математические связи

Для новой темы начни с `MathMorph.model(initialState)`. Автор задаёт математические
параметры, зависимости и смысловые шаги. Движок ведёт дискретизацию кривых,
материальные штрихи, рамку, подписи, расположение панелей, движение и раскрытие результата.
Для рассказа передавай план из `model.explain(...)` в `operation` главы
[MorphStory](morph-stories.md): оболочка пересчитывает параметры и связывает шаги с речью.
[«Одна связь — весь рисунок»](../examples/mathematical-relations/models.js) показывает
комплексный квадрат, нелинейную карту, фазовый портрет и сворачивание листа в 3D.
Ни одному из этих сюжетов не требуется новый метод движка.

```js
const model = MathMorph.model({ angle: 0 });
const z = model.value(({ angle }) => [Math.cos(angle), Math.sin(angle)]);
const square = z.map(([x, y]) => [x * x - y * y, 2 * x * y]);
const operation = model.explain({
  panels: [
    {
      title: 'Квадрат комплексного числа',
      axes: true,
      objects: [
        model.vector([0, 0], z, { label: 'z' }),
        model.vector([0, 0], square, { label: 'z²', pigment: 'orange' }),
        model.trace(square, 'angle', { pigment: 'orange' }),
      ],
    },
  ],
  steps: [
    {
      to: { angle: 2 * Math.PI },
      formula: 'arg z² = 2 arg z',
      explanation: 'За один оборот исходного числа квадрат делает два.',
    },
  ],
  result: square,
});
const drawing = await MathMorph.mount(shell.stage, operation);
shell.attachView(drawing.view);
drawing.render(frame, 'rotation');
```

`value(state => ...)`, `parameter(key)`, `map(fn)` и `join(other, fn)` образуют
чистый граф. Каждая связь вычисляется один раз в математическом снимке; координаты,
числа и текст читают тот же снимок. Состояние содержит конечные числа или тензоры;
шаг `to` непрерывно меняет выбранные параметры, сохраняя форму тензора.
Перемотка воспроизводит тот же результат без истории кадров.

| Объект                                                  | Что задаёт автор                                                                  |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `point(at, style?)`                                     | Связанную точку; видимый размер маркера выбирает движок                           |
| `vector(from, to, style?)`, `segment(from, to, style?)` | Концы в математических координатах или через `Value`                              |
| `polygon(vertices, style?)`                             | Математические вершины, в том числе связанные значения                            |
| `curve(fn, {domain, ...style})`                         | Параметрическую функцию и её интервал; `curve.at(t)` возвращает связь             |
| `material(map, {domain, grid?, text?, ...style})`       | Прямоугольную UV-область и карту в 2D/3D; `material.at(uv)` связывает с ней точку |
| `trace(value, parameter, {from?, ...style})`            | След связи при изменении одного математического параметра                         |
| `measure(from, to, style?)`                             | Измеряемые концы; длина, размерные линии и надпись рассчитываются вместе          |
| `label(text, at, style?)`                               | Текст или `Value<string>` и его математический якорь                              |

Общий `style`: `pigment`, `label`, `visible`, `side`, `quiet`, `dashed`.
`label` и `visible` принимают связи. Карта `material` и функция `curve` тоже принимают
`Value<function>`: расчёт физического состояния выполняется один раз, затем питает
все точки материала. `trace` изменяет указанный параметр от исходного значения
или `from` до текущего, сохраняя прочие параметры текущего снимка.

```js
const model = MathMorph.model({ bend: 0 });
const sheet = model.material(
  ([u, v], { bend: k }) =>
    Math.abs(k) < 1e-7 ? [u, v, 0] : [Math.sin(k * u) / k, v, (1 - Math.cos(k * u)) / k],
  {
    domain: [
      [-2.8, -1],
      [2.8, 1],
    ],
    grid: [14, 5],
    text: 'МАТЕРИАЛ',
  },
);
const mark = model.point(sheet.at([1.3, 0.45]), { pigment: 'orange' });
```

Карта с тремя координатами создаёт настоящую 3D-поверхность в `Viewport3D`:
сетка и штрихи нанесены на материал, участвуют в перспективе и глубине. Камера
и освобождение GPU-ресурсов остаются у viewport. 2D и 3D используют одни UV-штрихи.
Панель автоматически охватывает геометрию; `bounds` задаёт математический диапазон
для заранее известного сложного движения, `aspect:'free'` подходит для графиков
с независимыми масштабами осей. На узком экране панели располагаются колонкой.
Кривые получают адаптивную сетку, общую для всех состояний перехода: частые
колебания сохраняются, а перемотка не меняет число узлов. Совпадающий с поверхностью
след читается без ручного смещения по глубине; скрытые линии перекрываются телом.
Начальный 3D-ракурс следует лицевой стороне материала. Для смыслового ракурса
задай `camera: {direction: [0,5,3], up: [0,1,0]}` у панели — направление от предмета
к зрителю и вертикаль в математических координатах. Ручное вращение сохраняется
до сброса камеры или перемотки рассказа.

[Градиентный спуск](../examples/gradient-descent/models.js) — проверка независимым
автором: одна квадратичная функция связывает 3D-поверхность, линии уровня,
дискретный след, производную и предобусловливание. `MorphStory` ведёт главы,
параметры, озвучку и время; пример не содержит собственного рендерера.

`explain({panels, steps, result?})` возвращает готовый план. Каждый шаг содержит
`to`, `explanation`, необязательную `formula` — строку или связь.
`render(frame, cues)` принимает метки шагов либо одну метку всего преобразования;
`render(progress)` — ручной прогресс. Движок хранит единый ритм движения и пауз,
момент `frame.result` и reduced motion. `result` может быть числом или тензором.
`setOperation(plan)` переиспользует представление между главами.

### Готовые математические рассказы

`distribute`, `linear`, `project`, `derivative`, `integral`, `spring`, `deform`
собраны из того же модельного API. [«Математика меняет форму»](../examples/formula-objects/scene.js)
показывает эти композиции с озвучкой. Их можно применять целиком или писать свой
рассказ через `model`, сохраняя общих владельцев геометрии и рисунка.

| Вызов                                                | Видимое действие                                                                 |
| ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| `MathMorph.distribute(3,2,3)`                        | Разрезание площади: a(b+c)=ab+ac                                                 |
| `MathMorph.linear([[1,.8],[0,1]])`                   | Матрица переносит материал, базис и написанное                                   |
| `MathMorph.project(Math.PI/3)`                       | Радиус и синусоида связаны одним углом                                           |
| `MathMorph.derivative('x^2',1.5)`                    | Секущая становится касательной; увеличенный треугольник показывает предел        |
| `MathMorph.integral('x^2',0,3)`                      | Прямоугольники уточняют интеграл; выравнивание сохраняет ориентированную площадь |
| `MathMorph.spring({mass:1,stiffness:4,amplitude:1})` | Идеальная пружина передаёт энергию движению                                      |
| `MathMorph.deform({domain,parameter,map,grid,text})` | Одна карта переносит материал из начального в конечное состояние                 |

Производная принимает строку с переменной `x` либо чистую числовую функцию;
интеграл — конечную непрерывную функцию на возрастающем интервале.
`MathMorph.timing(frame,cues,plan.stages).progress` связывает поля исследования
с тем же временем. `shell.describeParameter(key,{label,format})` меняет смысл
поля между главами, сохраняя фокус и обработчики.

Для выражений над телами компонент владеет 2D/3D, камерой, материалом и надписями:

```js
import { MathMorph, Morph } from '@visual-storytelling/core';

const operation = MathMorph.formula('sum(partition(x, 3) * 2)', {
  x: MathMorph.body(6, Morph.capsule(0.62, 2.8)),
});
const math = await MathMorph.mount(shell.stage, operation);
shell.attachView(math.view);
// В render(state, frame, mode) существующего рассказа:
math.render(mode === 'story' ? frame : state.progress, 'computation');
```

Здесь целое делится на три равные части, каждая удваивается, затем части сливаются.
Результат этапа передаётся следующему без замены видимой поверхности. Промежуточные
числа, подпись операции, соответствие штрихов, контакт, инерция, раскрытие результата
и reduced motion вычисляются библиотекой. Автор задаёт выражение, входы и время.

```js
MathMorph.formula('sqrt(a^2+b^2)', { a: 3, b: 4 });
MathMorph.formula('1/(1+exp(-x))', { x: -2 });
MathMorph.formula('A * B', {
  A: [
    [1, 2],
    [3, 4],
  ],
  B: [
    [2, 1],
    [1, 3],
  ],
});
MathMorph.formula('diff(x^3, x)', { x: 2 });
MathMorph.formula('integral(t^2, t, 0, x)', { x: 3 });
MathMorph.formula(
  'softplus(x)',
  { x: 2 },
  {
    functions: { softplus: (x) => Math.log1p(Math.exp(x)) },
  },
);
```

Выражения и стандартные функции вычисляет mathjs; `partition` возвращает равные
части, `diff` — символическую производную в заданной точке, `integral` — численный
интеграл на конечном интервале. Собственная чистая функция возвращает число или
массив; траектории и надписи для неё создаёт тот же движок. Вычисления выполняются
при подготовке операции, перемотка их не повторяет. Принимаются конечные реальные
числа и массивы до 64 элементов; неопределённый результат отклоняется до смены сцены.

`measure: 'volume'` кодирует положительную величину объёмом куба, шара или капсулы;
`'value'` оставляет одинаковый объём для знаковых значений и нуля. По умолчанию
`'auto'` выбирает объём для положительных сопоставимых значений (диапазон до 64 раз),
иначе — числовые тела. Объём обозначает результат функции. Для объяснения её геометрического смысла
используй связи `MathMorph.model` или готовые рассказы выше.

`setOperation(operation)` заменяет данные после проверки; `render(frame, cue)`
принимает одну метку либо метки этапов, `render(progress)` — ручной прогресс 0…1.
`MathMorph.plan(operation)` позволяет подготовить выражение один раз и передать
тот же план нескольким представлениям. Для собственного окружения доступны
`MathMorph2D.mount(element, plan, {id})` и `MathMorph3D.mount(view, plan)`;
для операции внутри общей 3D-композиции передай `{layout:'scene'}`, чтобы размером кадра владела сцена, а не отдельный морфинг.
готовый `MathMorph.mount` объединяет их и управляет проекцией и рамкой камеры.
Опция `columns: 4` у этих трёх представлений закрепляет четыре ячейки в ряду
для встроенного вычисления; без неё число колонок подбирается по ширине окна.

Для измеряемых длины и площади используй [math-morph](../examples/math-morph/scene.js),
для числовых вкладов нейрона — [neuron-morph](../examples/neuron-morph/scene.js).

| Вызов                                                                                    | Видимое действие                                                                       |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `MathMorph.add(2, 4)`                                                                    | Части сходятся до соприкосновения, затем образуют целое                                |
| `MathMorph.divide(6, 3)`                                                                 | Целое раскрывается в три равные части; части расходятся                                |
| `MathMorph.multiply(2, 3)`                                                               | Ряд становится прямоугольником с единичной сеткой; та же площадь вытягивается в полосу |
| `MathMorph.power(6, 4)`                                                                  | Каждое умножение расширяет одну из двух сторон, сохраняя измеримую площадь             |
| `MathMorph.exponential(0, 3, 2)`                                                         | Показатель непрерывно меняется от 0 до 3, величина — от 1 до 8                         |
| `MathMorph.map({ from: 1, to: 3, range: [1, 9], value: x => x*x, label: (x,y) => ... })` | Собственная функция с указанным диапазоном для устойчивого масштаба                    |

Это модели положительных измеряемых величин: количество равно длине полосы или площади прямоугольника; толщина 3D-представления равна единице. Делитель — число частей 1…64, показатель повторной степени — целое 0…16. Большой непрерывный рост использует площадь, чтобы форма сохраняла видимую толщину; рамка сопровождает рост, а `volume.plan.bounds` доступна для сравнения на фиксированном масштабе. `MathMorph.plan(operation).sample(progress)` даёт тот же предметный кадр для собственной композиции. Итог открывается после операции; при сложении, разрезании и перегруппировке сохраняется количество, при росте меняется сама величина.

Промежуточные значения здесь обозначают длину или площадь: `2.5` допустимо для площади, а пересчёт кубиков требует отдельных целых предметов. В таком рассказе сохраняй объекты в группах, связывай перестановку с метками и раскрывай счёт после пересчёта; для готовых рядов есть [движение тензоров](tensor-motion.md).

## Числовые ячейки

```js
MathMorph.dot([2, -1, 0], [-0.5, 3, 2]); // пары → [-1, -3, 0] → сумма -4
MathMorph.vectorAdd([1, -2, 0], [-1, 4, 0]); // [0, 2, 0]
MathMorph.calculate('multiply', 2, -0.5); // -1
MathMorph.calculate('divide', -3, 2); // -1.5
```

Эти операции принимают конечные знаковые числа и ноль: одинаковые ячейки несут значения, их размер не означает величину числа (`plan.encoding === 'cells'`). `calculate` поддерживает `add`, `subtract`, `multiply`, `divide`, `power`. Скалярный расчёт и `dot` принимают 1…64 входа; у `dot` ряды имеют одинаковую длину. `vectorAdd` принимает 1…16 пар, деление и степень — два операнда. Неопределённый или бесконечный результат отклоняется до замены сцены.

Длинная сумма или `dot` автоматически проходит несколькими порциями с переносом
накопленного результата. Все исходные индексы и порядок вычисления сохраняются.
Передавай весь массив и одну метку: `computation.render(frame, 'calculation')`.
Число стадий следует длине входа; ручные `slice`, отдельные часы и повторные
вызовы расчёта не нужны. [«Как множество вкладов становится числом»](../examples/long-calculation/scene.js)
показывает скалярное произведение и баланс из 16, 32 или 64 вкладов через `MorphStory`.

Оба представления используют тот же `setOperation` / `render`; 2D строит непрерывный срез общего поля без подмены формы в середине. Материальные группы согласуют размеры до смешивания расстояний: сжатие нескольких кубиков не создаёт диагональных фасок, надпись получает то же преобразование.

`plan.result` — заранее вычисленное число либо массив для `vectorAdd`; показывать итог следует по `frame.result`, который появляется после завершения текущего этапа. `sample(p)` сохраняет `id` и `origins: [{ operand, index, value }]` через произведения до суммы. Знаки и подписи освобождают место перед контактом.

## Непрерывная цепочка

```js
const operation = MathMorph.chain(
  MathMorph.dot([2, -1], [0.5, 3]),
  { operator: 'add', value: 1 },
  { operator: 'apply', label: 'ReLU', value: (z) => Math.max(0, z) },
  { operator: 'multiply', value: 2 },
);
const computation = MathMorph2D.mount(stage, operation, { id: 'neuron' });

// В render(state, frame, mode) существующего SceneShell:
const shown = computation.render(mode === 'story' ? frame : state.progress, [
  'products',
  'sum',
  'bias',
  'activation',
  'next_weight',
]);
if (shown.stage === computation.plan.stages - 1 && shown.result !== undefined) {
  // Можно открыть пояснение к уже показанному результату.
}
```

Каждый следующий шаг принимает предыдущий скалярный результат: тело, положение,
размер и происхождение сохраняются, меняются его штрихи. `apply(input, label, fn)`
запускает самостоятельную скалярную функцию. `chain` также принимает другую цепочку;
векторный результат сначала должен быть сведён к скаляру.

`render(frame, cues)` принимает одну метку для всей операции или по одной на этап.
Повторенная подряд метка делит свой интервал между этими этапами. Завершённый
результат удерживается до начала следующей метки. Политика reduced motion общая:
тело меняется между опорными состояниями, время раскрытия результата сохраняется.
При `render(number)` используется системная настройка движения.

Числовые ячейки автоматически размещаются по доступной ширине, сохраняют читаемый
масштаб и переходят в несколько рядов. Высота представления следует композиции;
2D-компонент монтируется прямо в HTML-контейнер. В 2D формулы переносятся по измеренным
штрихам. Собственные `foreignObject`, пересчёт мобильных координат и пороги раскрытия
результата для арифметики не нужны.

## Надпись внутри контура

```js
import { node } from '@visual-storytelling/core';
const answer = node(drawing, 'answer', 0.858, {
  shape: 'ellipse',
  width: 74,
  size: 30,
  pigment: 'green',
});
answer.at(180, 120);
answer.value(nextValue);
// Связь измеряет тело: SvgLayout.connect(answer.shape, next.shape, ...).
```

`node` центрирует действительные штрихи и оставляет внутренний отступ; размер букв
не падает ниже `minSize` (16 по умолчанию). Если места всё же мало, растёт тело.
`width`, `height` и `anchors` сообщают его актуальные границы для композиции.
Для уже существующей фигуры используй `lettering(..., {bounds: {width, height,
shape: 'ellipse', padding: 6}})`: владелец измерит и центрирует надпись. Недостаточный
контейнер при минимальном размере помечается `data-layout-error`; `node` решает это
изменением собственного контура. `paragraph` переносит длинные внешние пояснения.
`SvgLayout.along(label, route, {avoid: [...nodes, ...labels, ...routes], space})`
размещает подпись рядом со связью, сохраняя расстояние до остальных видимых объектов
и маршрутов. Собственная линия также остаётся вне штрихов надписи.

## Управление полем

Для собственных поз и моделей доступны `InkFusion` / `Physics2D.fusion` и `VolumeMorph`: `setShapes(sources, targets)` и кадры с соответствующими позами, `morph`, `tension`. Это нижний уровень для предметной геометрии; обычные рассказы используют операции выше. `VolumeMorph` владеет полем расстояний и sphere tracing, `InkFusion` — сопоставлением штрихов и локальными перемычками. Те же владельцы обслуживают `Morph`, `MathMorph` и `InkMorph`; дополнительного рендерера надписей в сцене нет.

## Столкновения с меняющейся формой

```js
const contact = Physics3D.morph(world, volume.surface, {
  id: 'quantity',
  cellSize: 0.08,
});
// 2D: Physics2D.morph(world, inkFusion, { id: 'ink', scale: 100, cellSize: 1 });
```

Оба адаптера строят Rapier-коллайдер из текущего поля видимой поверхности. Окружающие тела опираются, отталкиваются и падают при открытии зазора; этот путь показан в [morph-contact](../examples/morph-contact/scene.js). Форма здесь — задаваемая сценарием граница, реакцию окружающих тел рассчитывает общий физический мир. `cellSize` — точность контакта: в единицах сцены для 3D, рисунка для 2D; меньшая ячейка увеличивает стоимость. `friction` и `restitution` задают контакт. Положение 3D задаётся transform владельца всей композиции (`volume.object`), привязка следует ему вместе с подписями; иерархия с shear отклоняется явно. В 2D `at` задаёт начало рисунка в физическом мире. Поверхность имеет одну физическую привязку, удаление любой стороны освобождает её; snapshots сохраняют native handles.

Часы и перемотка остаются у существующего плеера. Для живой физики используй `PhysicsPlayer`; для воспроизводимого рассказа обновляй форму на фиксированных шагах общего мира и восстанавливай его snapshot перед обратным проходом. Сохранение объёма, массы или энергии задаётся предметной моделью, а произвольная интерполяция форм сама по себе его не гарантирует.
