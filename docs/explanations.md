# Композиция объяснения

Начните с `graph-lab`: точка показывает измеренный путь, треугольник раскрывает наклон,
а прогноз проверяется той же моделью движения. Первый экран отвечает на один вопрос.
Назовите предмет, связь и вывод; дайте им место в этом порядке.

```js
import { explanationLayout } from '@visual-storytelling/core';
import { disclosure } from '@visual-storytelling/core/controls';

const layout = explanationLayout(shell.stage);
layout.controls.append(shell.fields);
layout.footer.append(shell.actions);
// Рисунок — layout.figure, пояснение — layout.notes.
const detail = disclosure(layout.notes, {
  label: 'Откуда взялось число?',
  onChange: (open) => shell.input({ detail: open }),
});
// В render(values): detail.set(values.detail); заполнить detail.body из модели.
// В shell.onDispose: detail.dispose(); layout.dispose().
```

`explanationLayout` размещает рисунок и чтение рядом, а в узком контейнере — последовательно.
Размер письма сохраняется. `figure`, `controls`, `notes`, `footer` — места существующих
владельцев; компоновка не создаёт своих часов, истории или параметров.
Классы `ve-eyebrow`, `ve-reading`, `ve-equation`, `ve-note` и обычный `mark` задают
иерархию текста в `notes`. Подписи к конкретным предметам остаются в самом рисунке.

`shell.input(patch)` принимает пользовательское действие через параметры и историю.
Раскрытие, прогноз и проверка входят в то же принятое условие. `Story.requested`
нужен следующему действию, `Story.presented` — инспектору подтверждённого рисунка.
У `SceneStory` переход `shell.input({chapter, sceneTime})` берёт условия целевой главы;
явно переданные величины их уточняют. `sceneTime` нормирован от 0 до 1.

| Основа              | Что менять                                                            | Общие средства                                                   |
| ------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `graph-lab`         | `model.js`: зависимость; `drawing.js`: оси; `scene.js`: вопрос и опыт | `plot.interval`, `placeLabels`, `disclosure`, `predictionPrompt` |
| `connected-diagram` | `scene.js`: последовательность; `drawing.js`: предметы и связи        | `Viewport3D`, `InkConnection3D`, `disclosure`                    |
| `area-lesson`       | `story.json`: главы; `scene.js`: условия и пояснения                  | `IllustratedStory`, `areaDiagram`, `predictionPrompt`            |

`plot.interval` получает две точки данных. Заливка и надписи Δx/Δy происходят из
того же интервала. Если места для подписи малого интервала недостаточно, она
скрывается в рисунке; полный расчёт остаётся у автора в соседнем пояснении. `placeLabels` расставляет измеренные границы подписей в заданном
порядке без истории кадров. `lettering.bounds` учитывает полное перо.

Перо `heading` выделяет мысль, `body` объясняет, `note` отводит вспомогательному
тексту спокойную роль. Кириллица, цифры и математические знаки используют те же
контуры в WOFF2, SVG и объёмном рисунке. Синий связывает предмет с вычислением,
другой пигмент обозначает сравнение, жёлтый маркер выделяет короткий вывод.

Проверьте длинную фразу и крайние значения, раскрытие клавиатурой, undo/redo,
быструю смену условий и возврат времени. Обе темы и узкий контейнер должны
сохранять предмет, причинную связь и читаемую подробность. Reduced motion
сохраняет смысловые состояния. PNG и HTML передают весь составной лист;
SVG выпускается для сцен, целиком представленных в SVG.
