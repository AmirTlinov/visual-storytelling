# Объяснение внутри кадра

Рисунок интерактива и ролик используют одну композицию. `SceneShell` по умолчанию
собирает 1280 × 720: заголовок, предмет и предметные действия.
`SceneStory` и `IllustratedStory` наследуют этот кадр. Подготовленное сравнение маршрутов
использует 1280×960 (4:3), чтобы оба опыта и их подписи помещались на узком окне.
В 16:9 видео композиция вписывается целиком; если её показанная ширина меньше 766 px,
«Было/Стало» показываются последовательно тем же владельцем, что в узкой карточке. Единственный плеер стоит
под рисунком вне его масштаба: области нажатия от 44 CSS px, текст от 16 CSS px;
на узкой поверхности элементы переносятся. Окно меняет масштаб рисунка; условия,
перемотка и выбор подробности сохраняют композицию.

Тетрадный разбор и персонажная постановка показываются отдельными кадрами.
`SceneShell` с `presentation: 'stage'` отдаёт весь кадр декорации без сетки
и внешнего заголовка; общие поля и выбор главы располагаются под ним.
`presentation: 'explanation'` возвращает композицию разбора. В `SceneStory`
это свойство принадлежит главе: `characterChapter` выбирает `stage`,
`inkChapter` — `explanation`. Переход происходит вместе с готовым рисунком;
часы, модель, история и плеер сохраняются. Живая схема внутри доски персонажа
остаётся частью постановки; отдельное тетрадное объяснение получает свою главу.

Эталон [«Как GPT выбирает следующее слово»](../examples/gpt-model/story.json)
связывает фразу, residual stream, attention, MLP и распределение продолжений.
Вычисление работает локально: [model.js](../examples/gpt-model/model.js) возвращает
все промежуточные значения. [computation.js](../examples/gpt-model/computation.js)
передаёт те же входы с адресами `TensorData` в `MathMorph`. Схема, алгебра,
геометрическая проекция и поток данных в регистрах показывают один выбранный шаг.

```js
const shell = SceneShell.mount(root, { title: 'Скорость — это наклон', parameters });
const view = surface(shell.stage, {
  id: 'distance',
  title: 'Путь по времени',
  description: 'Время и путь.',
  width: shell.stage.clientWidth,
  height: shell.stage.clientHeight,
  grid: false,
});
// Подписи, формула и действия принадлежат этому рисунку.
const pointAction = svgButton(point.content, {
  x: -24,
  y: -24,
  width: 48,
  height: 48,
  label: 'Измерить наклон',
  onPress: () => shell.input({ detail: true }),
});
shell.onDispose(() => {
  pointAction.dispose();
  view.dispose();
});
```

Первым зритель замечает предмет, затем изменение, затем короткий вывод рядом
с его причиной. Числа, подписи и формулы относятся к видимой геометрии.
Длинное объяснение раскрывается последовательностью действий и глав.
Текстовые панели, раскрывающиеся вопросы и субтитры не заменяют рисунок.
Реплики доступны экранному диктору; озвучка подключается по запросу.

`shell.input(patch)` проводит действие через параметры и историю. Прогноз и
проверка входят в то же принятое условие. `Story.requested` нужен следующему
действию, `Story.presented` — описанию показанного рисунка. Переход
`shell.input({ chapter, sceneTime })` использует условия целевой главы;
`sceneTime` нормирован от 0 до 1. Результат проверки задаёт предметная модель.

| Файл эталона                  | Ответственность                                                        |
| ----------------------------- | ---------------------------------------------------------------------- |
| `model.js`, `checkpoint.json` | Исполняемая модель, обученные веса, полный trace                       |
| `scene.js`                    | Порядок объяснения, предметные действия, выбор уровня и точки зрения   |
| `drawing.js`                  | Предметная композиция через публичные перо, письмо, кнопки и раскладку |
| `computation.js`              | Числа модели, их адреса и анимация MathMorph                           |

`shell.layout` возвращает логические `width/height`, фактические
`displayWidth/displayHeight`, `scale` и `compact`. Оболочка обновляет их при смене
поверхности; они не входят в checkpoint. При `compact` рисунок оставляет одну
основную операцию и раскрывает соседние шаги последовательно. Размер существенной
надписи — не меньше `16 / scale`, области действия — `44 / scale` в координатах
композиции. Измеряйте текст через `lettering.bounds`, затем передавайте реальные
размеры в `placeLabels`. Не сжимайте насыщенный широкий рисунок целиком.

Общие поля и кнопки оболочки сохраняют физический размер текста от 16 px и
область нажатия от 44 px. При ширине кадра меньше 640 px кнопка «Условия»
раскрывает поля и историю в native popover, сохраняя место предмета.
Заголовок текущей главы стоит в одной строке с режимами над бумагой и открывает
меню глав без стрелки и подчёркивания. Длинное название сокращается по доступной
ширине; полное название доступно экранному диктору и в меню. Если сцена скрыла
все общие поля и предоставляет собственную навигацию, пустая кнопка не появляется.
Для собственной навигации задайте `navigation: false`: кнопки глав, режимов и
отмены скрыты, общая камера, часы и история продолжают работать.
`heading: false` независимо отключает только заголовок.
Раскрытие не входит в checkpoint и в экспорт композиции; фокус уже редактируемого
поля сохраняется при смене ширины. Режим `stage` сохраняет общие условия под кадром.

Для предположения отметьте cue как `awaitInput: true` и задайте
`canContinue(cue, moment)`. Общий `Story` останавливает часы в начале этого cue,
в том числе при задержанном кадре и ускоренном воспроизведении. Ответ пользователя
проходит через `shell.input`; предметная модель определяет результат проверки.
Явная перемотка и выпуск могут показывать любой выбранный кадр.

`plot.interval` получает две точки данных и вычисляет геометрию приростов и
их надписи. Для малого интервала остаётся точная геометрия; полный расчёт
показывает связанная формула. `trace.showAhead(false)` скрывает будущую линию
на время прогноза. Названия осей передаются в `xLabel`/`yLabel`, значения у точек —
в `plot.label`. После изменения модели один `plot.layout()` размещает деления,
названия, значения и измерения вместе, учитывая линии всех графиков на одном листе.
Порядок вызовов `layout()` не меняет результат. `plot.avoid(element)`
защищает расположенную рядом формулу или действие. Агент задаёт величины и связи;
зазоры и перенос подписей принадлежат графику.

```js
const value = chart.label('result', '20 м', { at: [10, 20], pigment: 'blue' });
// В render: данные, состояние и надпись обновляются вместе.
trace.at(model.time, model.distance);
value.at(model.time, model.distance);
value.text(`${model.distance} м`);
chart.layout();
```

У 2D, `SvgLayout.along` и экранных подписей `Viewport3D` один `placeLabels`:
измеренные прямоугольники, защищённые предметы, отрезки, поля и приоритеты.
`SvgLayout.viewport(space)` переводит видимую область в координаты рисунка;
её выпуклая `boundary` сохраняет настоящие края при переносе и повороте.
Одинаковые данные дают одинаковое размещение без истории кадров. `status: 'placed'`
означает свободное место с требуемым зазором; `overflow` явно обозначает нехватку
пространства. График, SVG и 3D предлагают доступное действие «Ещё подписи» только для
этого случая; `SceneHandle.presentation().layoutOverflow` сообщает их агенту.
Плотные деления сохраняют координаты, вынесенная подпись — линию к своей точке.
В 3D размещение включено по умолчанию, `labelObstacles` защищает важные предметы,
надписи на поверхностях автоматически защищены и остаются частью геометрии.
Для SVG `SvgLayout.overflow(space, { region })` подключает тот же механизм:
добавь `reserve()` в препятствия до размещения, передай неуместившиеся подписи
в `update([{ id, label, subject }])`, освободи через владельца сцены.
`SceneHandle.onDispose(cleanup)` связывает дополнительные ресурсы представления
с единственным `dispose`; HTML-оболочка SVG использует исходный handle.

Для пространственной SVG-проекции `SvgLayout.along(..., { region })` принимает
настоящий обрезанный viewport. Подписи осей и вектора сохраняют связь с предметом
при повороте, масштабе и переносе через того же владельца раскладки.

`lettering.bounds` учитывает полное перо; `pen.arrow().between(a, b)` переносит
стрелку вместе с её предметом.

Фоновая сетка принадлежит оболочке. Для измерения передайте `surface` сетку
с шагом и началом в координатах модели и задайте `paper: false` у оболочки:
камера двигает рисунок и измерительную сетку вместе, в одной области видна одна сетка.

Перо `heading` выделяет мысль, `body` подписывает предмет, `note` обозначает
вспомогательное построение. Профили прямые, стандартный штрих нейтральный.
В эталоне фиолетовый обозначает residual stream, охра — attention, зелёный — MLP
и полученный результат. Чернила плотные; сетка и заливки спокойные.

Проверяйте реальные кадры: крайние значения, выбор клавиатурой, undo/redo,
быстрый ввод, обратную перемотку и обе темы. На узкой карточке сохраняются
выбранные пропорции и все состояния. Большую панель открывает штатная кнопка карточки Codex;
сцена сохраняет целый кадр и не дублирует это действие своим управлением.
Переход между поверхностями сохраняет условия, историю и паузу без захвата
фокуса. Подробность раскрывается возле предмета или через его камеру.
Видео и PNG выпускают полный авторский рисунок без плеера.
`presentation().frame` описывает композицию; размеры плеера проверяются отдельно
в физических CSS px. В большой панели проверяйте `unreadableText` и реальные
надписи. При reduced motion результат
действия остаётся видимым. MP4 всегда имеет пропорции 16:9. SVG доступен сценам,
которые предоставляют весь кадр в векторном виде. Общий `SceneShell` сохраняет
в нём заголовок, предметные действия и текущий рисунок вместе со шрифтами.
Canvas и неподдерживаемая смешанная композиция требуют PNG/HTML/MP4 либо
явного `SceneHandle.exportSVG()` для всего кадра; молчаливое обрезание запрещено.
