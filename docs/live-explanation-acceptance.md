# Живое визуальное объяснение: журнал приёмки

Контракт и последовательность работ: [milestone в Linear](https://linear.app/main-cluster/document/zhivoe-vizualnoe-obuyasnenie-kontrakt-realizacii-i-priyomki-fea324f2a046).
Этот журнал хранит доказательства и открытые условия, а не заменяет приёмку установленного выпуска.
Целевая платформа milestone — macOS Apple Silicon; Linux и другие ОС отложены пользователем.

## GUI-561: группы и остаток

Кандидат: плагин 0.17.3, библиотека 0.30.3, ветка `codex/live-explanation`.
Модель `division`, `ExplanationDocument` и `mountExplanation` используют действующие
Story, SceneShell, ProjectStore и SessionDirectory. Начальное создание и содержательные
правки работают с заранее собранным представлением; runtime закрепляется сразу.
Сборка переносимого архива остаётся операцией выпуска.

### Исходный замер

12 октября 2026, macOS Apple Silicon. Независимый агент создавал три примера через
CLI установленного выпуска 0.16.0 / библиотеки 0.29.0 и проверял их в Chrome.
Отсчёт включает работу агента с момента получения задания. Это исходный авторский
маршрут; нативная карточка Codex в этот замер не входит.

| Пример | Первый проверенный кадр | Готовый опыт | Байты исходника | Команды CLI |
| --- | ---: | ---: | ---: | ---: |
| Остаток | 155 с | 173 с | 3226 | 9 |
| Рычаг | 106 с | 115 с | 2943 | 6 |
| Вероятности | 67 с | 73 с | 3281 | 4 |

Второй и третий прогоны использовали уже изученный API. В рычаге потребовались
одна правка кода и исправление пути shell; в остальных — без правок кода.
Исторические результаты зафиксированы в этом журнале. Исходная временная
рабочая копия удалена; её игнорируемые артефакты больше недоступны.

### Проверки кандидата

- Точная целочисленная модель сохраняет `N = q·d + r`, `0 ≤ r < d`.
  Рисунок поддерживает `0 ≤ N ≤ 36`, `1 ≤ d ≤ 12`; это границы рисунка.
  Промежуточная группировка показывает только уже образованные группы.
- Browser-проверка охватывает 135 сочетаний входов, прогресса и масштаба;
  отдельные кадры 960/375 px, светлая/тёмная темы, reduced motion.
- Сквозной SDK-host запускает настоящий MCP из комплекта: частичный ввод,
  подтверждение в том же iframe/SceneHandle, правки, повтор requestId, отклонение
  ошибки до записи, undo, повторное открытие, HTML и переносимые исходники.
  Создание проекта заняло 58–59 мс; подтверждённые изменения — 145–167 мс.
  Эти значения относятся к техническому пути и **не включают генерацию агентом**.
- Независимые ревью выявили и проверили исправления сохранения времени/условий,
  скорости проигрывания, заголовка, тихих речевых интервалов, отмены и доверия
  к закреплённому исполняемому пакету. Невалидный будущий кадр не принимается
  как успешная авторская правка.
- Базовый пакет 0.17.0 прошёл 626 Node-проверок и 23 Python-проверки;
  отдельная миграция между реально различающимися доверенными pin прошла
  create → migrate → viewer state → edit → undo → reopen.

### Пробный прогон нового автора

Первый независимый запрос к подготовленному SDK-host установленного 0.17.0:
«Покажи, почему 23 камня не разбиваются на полные группы по 4; дай проверить
переход к полным группам». Агент — GPT-6-luna, low. От диспетчеризации задания
первый подтверждённый кадр занял около 16,7 с. Объявленное агентом завершение
через 65 с **отклонено**: агент перемотал рассказ, не проверив изменение входа.
После исправления проверены 23 → 24, q: 5 → 6, r: 3 → 0; до подтверждённого
завершения прошло около 249 с, включая замечание и исправление. Запись событий
зафиксирована в журнале; исходное заявление сохранено как неуспешное.

Прогон выявил лишнюю проверку пустого окна, ненужную собственную партитуру,
ошибочный вызов tools/list и затруднения с режимами. Транспорт benchmark также
добавил служебную работу с HTTP/auth; эти затраты не выдаются за свойства
нативного Codex. Цель 5/20 не подтверждена этим прогоном.

В 0.17.1 обязательный вход сокращён до `model: {kind, count, divisor}`.
Единый валидатор дополняет структурные поля; количество и делитель остаются
обязательными. Навык начинает готовый опыт с создания предмета и различает
перемотку и изменение входа.

Второй запрос к пустому подготовленному SDK-host установленного 0.17.1:
«Почему 14 жетонов не раскладываются без остатка по 3? Дай проверить, что
меняется, если добавить один». Агент GPT-6.1-sol, low предварительно изучил
общий API и навык, без готовой сцены под этот вопрос. Проверены 14 → 15,
q: 4 → 5, r: 2 → 0 и реальный читаемый кадр. Все три MCP-вызова успешны.

| Событие | От регистрации задания | От передачи агенту |
| --- | ---: | ---: |
| Первая команда | 13,024 с | 8,242 с |
| Первый содержательный кадр | 13,098 с | 8,316 с |
| Подтверждённый кадр | 13,201 с | 8,419 с |
| Проверенное изменение входа | 27,063 с | 22,281 с |

Отметка регистрации — миллисекундная; граница передачи агенту взята из
времени вызова с точностью до секунды. Координационные 4,782 с сохранены,
из полного времени не вычитаются. Создание MCP заняло 65 мс; первое
содержимое появилось за 72,4 мс после прихода полного входа в SDK-host.
Аппаратная среда: Apple M5 Max, 18 логических CPU, 128 ГБ, arm64;

### Исправления надёжности в 0.17.2

Явные входы операции сохраняются в журнале: команда вернуть авторское число
исполняется и при неизменном файле, независимые условия зрителя сохраняются.
Каждый payload проверяется отдельно; связи между совместно изменяемыми
представлениями проверяются по целому кандидату. Плохая промежуточная операция
не может скрыться за последующим перезаписыванием.

Применённая авторская ревизия сопровождает каждый отчёт кадра. Подтверждение
записи, применения и наблюдения различаются; отказ или задержка подтверждения
не приписывают новый кадр старому исходнику. Повтор доставки сохраняет ввод
зрителя и не повторяет запись. ID создания закрепляется до открытия сеанса;
неудачная запись реестра не публикует успешный результат в памяти.

Независимое ревью проверило apply → timeout → retry → late report → viewer input
→ отказ второй попытки → восстановление. Реальный browser regression проверил
14 → авторские 17 → ручные 18 во время ожидания кадра; после восстановления
число 18 сохраняется, в том числе после открытия нового iframe из checkpoint.
Полный набор протокола — 642 Node + 23 Python PASS; адресный набор свежего
комплекта — 44 PASS. GitHub-ревью дополнительно выявило потерю временного
резерва визуального действия на границе озвученных глав. Исправление добавляет
резерв в завершающую паузу ровно один раз; build/check и 19 адресных проверок
PASS, включая следующую озвученную/тихую главу, конец истории и remount.
Эти исторические результаты не закрывают нативную приёмку.

### Подключённый API и короткий путь в 0.17.3

13 октября переподключённый нативный API 0.17.2 проверен в Codex. Создание
13/3, изменение зрителем до 14, авторская правка до 15 и повторное открытие
сохранили модель и положение 5,2 с. Подтверждение `prepared` сохранялось;
оно не доказывает видимые пиксели. Несмотря на разрешение пользователя,
автоматическая проверка доступа запретила управление окном Codex. Отдельный
MCP-browser не предоставил раскрытую карточку.

В свежем нативном запросе 22/6 → 24/6 агент GPT-6.1-sol low получил задание
в 07:52:35,235 UTC. Первая команда — через 7,790 с, подключённый `prepared` —
10,880 с, проверенные модельные ответы — 22,927 с. Наблюдённого первого кадра
нет. Цели 5/20 этим прогоном не достигнуты.

Кандидат 0.17.3 использует `story_create(sessionId)` для нового объяснения
в действующей карточке через существующую навигацию. Повтор ID возобновляет
незавершённую доставку; созданный проект переживает закрытую карточку.
`story_control(detail: "model")` возвращает результат модели в ответе действия.
Запись метаданных проекта обновляется в общей очереди реестра: конкурентные
изменения сборки и сеанса больше не могут откатить подтверждённую доставку.
Копия предварительного кадра удаляется при позднем выборе действующего сеанса.
Метрики приложения привязаны к renderer, generation и началу его часов;
`prepared`, возможность отрисовки и проверенные пиксели различаются.

Независимое ревью выявило и проверило исправления связи метрик, ответа простой
паузы, атомарного реестра и удаления позднего предварительного кадра.
Первый полный прогон: 652/653 Node PASS. Единственное падение — старое
ожидание речевой паузы; поле `text` входит в озвучку, для тишины нужно `say: ""`.
Ожидание исправлено, добавлена проверка явной тишины; 20 адресных проверок PASS.
Python: 23 PASS. Итоговый выпуск проверяется заново после этой правки.

Свежий запрос 26/8 → 32/8 использовал настоящий установленный 0.17.3 / core 0.30.2 в
изолированном SDK-host Chromium. Общий runtime был прогрет нейтральной моделью,
вопрос и будущая сцена заранее неизвестны. От точной доставки задания агенту
до первой команды — 5,925 с, первого проверенного PNG — 6,230 с,
изменённой модели и её кадра — 17,593 с, завершения после просмотра обоих PNG —
26,330 с. Само создание MCP заняло 129 мс. Работа агента и визуальная проверка
входят в итог; из него ничего не вычитается. Модель и рисунок согласованы:
три группы по восемь с остатком два превращаются в четыре полные группы.
Это SDK-проверка; цели 5/20 и нативную приёмку она не закрывает.

После этого замера пользователь указал на системный список скорости.
В core 0.30.3 он переведён на `selectControl`, который уже обслуживает главы
и условия: общий внешний вид меню, клавиатура, закрытие и жизненный цикл.
Системный `select` и отдельный обработчик его `change` удалены. Скорость вне
готового списка, например 1,7×, отображается точно без ложного выбранного пункта.
Эта правка требует свежей сборки и проверки конечного комплекта.

Среда: Apple M5 Max, 18 логических CPU, 128 ГБ, macOS arm64;
Node 24.14.1, Playwright 1.63.0. Новые отчёты, кадры и журналы проверок:
`artifacts/live-milestone/2026-10-13/`. Перед удалением рабочей копии их нужно
сохранить в основном каталоге проекта.

### Открытая приёмка

GUI-561 остаётся In Progress. Нужны нативный проход установленного кандидата в
Codex, непрерывная оценка движения и новый замер первого кадра ≤5 с / готового
опыта ≤20 с **с работой агента**. SDK-host и скорость одной операции не закрывают
эти требования. Остальные слайсы и milestone остаются открытыми.
