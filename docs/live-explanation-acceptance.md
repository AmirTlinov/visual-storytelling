## GUI-561: группы и остаток

Кандидат: плагин 0.18.2, библиотека 0.31.2, ветка `codex/live-explanation`.
В зафиксированном выпуске 0.18.2 модель `division`, прежний документ и его mount использовали действующие

Сборка переносимого архива остаётся операцией выпуска.

### Проверки кандидата

- Точная целочисленная модель сохраняет `N = q·d + r`, `0 ≤ r < d`.
  Рисунок поддерживает `0 ≤ N ≤ 36`, `1 ≤ d ≤ 12`; это границы рисунка.
  Промежуточная группировка показывает только уже образованные группы.
- Browser-проверка охватывает 135 сочетаний входов, прогресса и масштаба;
  отдельные кадры 960/375 px, светлая/тёмная темы, reduced motion.
- Сквозной SDK-host запускает настоящий MCP из комплекта: частичный ввод,
  подтверждение в том же iframe/SceneHandle, правки, повтор requestId, отклонение
  ошибки до записи, undo, повторное открытие, HTML и переносимые исходники.
  Создание проекта заняло 58–59 мс; подтверждённые изменения — 145–167 мс.
  Эти значения относятся к техническому пути и **не включают генерацию агентом**.
- Независимые ревью выявили и проверили исправления сохранения времени/условий,
  скорости проигрывания, заголовка, тихих речевых интервалов, отмены и доверия
  к закреплённому исполняемому пакету. Невалидный будущий кадр не принимается
  как успешная авторская правка.
- Базовый пакет 0.17.0 прошёл 626 Node-проверок и 23 Python-проверки;
  отдельная миграция между реально различающимися доверенными pin прошла
  create → migrate → viewer state → edit → undo → reopen.

### Исправления надёжности в 0.17.2

Явные входы операции сохраняются в журнале: команда вернуть авторское число
исполняется и при неизменном файле, независимые условия зрителя сохраняются.
Каждый payload проверяется отдельно; связи между совместно изменяемыми
представлениями проверяются по целому кандидату. Плохая промежуточная операция
не может скрыться за последующим перезаписыванием.

Применённая авторская ревизия сопровождает каждый отчёт кадра. Подтверждение
записи, применения и наблюдения различаются; отказ или задержка подтверждения
не приписывают новый кадр старому исходнику. Повтор доставки сохраняет ввод
зрителя и не повторяет запись. ID создания закрепляется до открытия сеанса;
неудачная запись реестра не публикует успешный результат в памяти.

Независимое ревью проверило apply → timeout → retry → late report → viewer input
→ отказ второй попытки → восстановление. Реальный browser regression проверил
14 → авторские 17 → ручные 18 во время ожидания кадра; после восстановления
число 18 сохраняется, в том числе после открытия нового iframe из checkpoint.
Полный набор протокола — 642 Node + 23 Python PASS; адресный набор свежего
комплекта — 44 PASS. GitHub-ревью дополнительно выявило потерю временного
резерва визуального действия на границе озвученных глав. Исправление добавляет
резерв в завершающую паузу ровно один раз; build/check и 19 адресных проверок
PASS, включая следующую озвученную/тихую главу, конец истории и remount.
Эти исторические результаты не закрывают нативную приёмку.

### Подключённый API и короткий путь в 0.17.3

сохранили модель и положение 5,2 с. Подтверждение `prepared` сохранялось;
оно не доказывает видимые пиксели. Несмотря на разрешение пользователя,
автоматическая проверка доступа запретила управление окном Codex. Отдельный
MCP-browser не предоставил раскрытую карточку.

В свежем нативном запросе 22/6 → 24/6 агент GPT-6.1-sol low получил задание
в 07:52:35,235 UTC. Первая команда — через 7,790 с, подключённый `prepared` —
10,880 с, проверенные модельные ответы — 22,927 с. Наблюдённого первого кадра
нет. Цели 5/20 этим прогоном не достигнуты.

Кандидат 0.17.3 использует `story_create(sessionId)` для нового объяснения
в действующей карточке через существующую навигацию. Повтор ID возобновляет

`story_control(detail: "model")` возвращает результат модели в ответе действия.
Запись метаданных проекта обновляется в общей очереди реестра: конкурентные
изменения сборки и сеанса больше не могут откатить подтверждённую доставку.
Копия предварительного кадра удаляется при позднем выборе действующего сеанса.
Метрики приложения привязаны к renderer, generation и началу его часов;
`prepared`, возможность отрисовки и проверенные пиксели различаются.

Независимое ревью выявило и проверило исправления связи метрик, ответа простой
паузы, атомарного реестра и удаления позднего предварительного кадра.

ожидание речевой паузы; поле `text` входит в озвучку, для тишины нужно `say: ""`.

### Размер меню и сохранение запроса в 0.18.2

Общий `selectControl` измеряет содержимое, сохраняет минимальную ширину кнопки
и ограничивает список доступным экраном. Короткие варианты скорости обходятся

requestId. ProjectStore теперь сохраняет ID, путь и проверенный ввод одной
durable-записью до создания папки и manifest. Повтор после прерывания восстанавливает
тот же проект; чужие файлы, иной manifest и изменённый ввод отклоняются.

Ветка включает принятые исправления аудио, воспроизведения и кэша выпуска

озвучки при ошибке публикации. Существующие пользовательские pin не меняются
автоматически. Проверки объединённого кандидата фиксируются в отчёте выпуска.
