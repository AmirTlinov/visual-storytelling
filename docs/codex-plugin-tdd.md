# Visual Storytelling · устройство плагина

Плагин превращает запрос в редактируемое визуальное объяснение. Основные формы — иллюстрация, схема, график, опыт, математический разбор, урок и персонажный рассказ. Голос и видео подключаются по задаче. Библиотека, каталог, API, навык и установочный архив выпускаются одной версией.

SDK Codex остаётся на границе плагина. Автономная сцена использует тот же `SceneHandle`, часы и предметную модель.

## Достоверное состояние

`Story.requested` — последнее принятое условие; следующий быстрый ввод продолжает его. `Story.presented` — последний успешно отрисованный момент. Подготовка имеет явные состояния и ошибку; отменённая подготовка ничего не публикует. При ошибке подготовки прежний кадр сохраняется, повтор доступен. Ошибка самого render снимает подтверждение кадра.

Поля и история работают с принятым условием. Синхронная ошибка подготовки сохраняет принятый шаг истории; отклонённый до принятия ввод его не создаёт. `inspect().rendering` сообщает оба состояния; обычный capture и snapshot описывают подтверждённую модель. Камера записывается только вместе с совместимым кадром. `SceneHandle.ready()` позволяет команде и экспорту дождаться подготовки. Ресурсы представления освобождает его `dispose`.

`SceneCheckpoint.values` сохраняет зарегистрированные параметры, `subject` — вложенную модель через её владельца. `StoryOptions.checkpoint.encode/decode` связывает её со Story; widgetState и текущие HTML/PNG используют тот же checkpoint. Собственный `SceneSubject.restore` принимает условие синхронно, Promise ожидает подготовку. Новый ввод отменяет применение камеры и выбора старого восстановления с `scene_restore_superseded`. [Контракт и пример](authoring.md) определяют проверку входов и восстановление.

Формула вычисляет непосредственные входы каждой выходной ячейки. Их одновременно используют вычисление, группировка движения и инспектор. Точность `exact` охватывает поддержанные операции, включая последовательные свёртки вариативного матричного `multiply` со скалярами; пользовательская непрозрачная функция обозначается `conservative`.

## Авторство и ревизии

`story_open` открывает явно выбранный пример, проект или сессию; без входа возвращает рекомендуемые основы из общего каталога без создания сессии. Onboarding явно использует единственный эталон `gpt-model`.

`story_create(document)` сохраняет компактный документ и открывает живую карточку готового приёма. Валидный частичный ввод может показать предварительный опыт до результата вызова; этот кадр ещё не подтверждает ревизию проекта. Финальный документ продолжает работу в том же iframe и SceneHandle. Последующие `story_edit(operations)` меняют модель, представления или партитуру через владельца сцены. [Контракт и пример](../skills/visual-explainer/references/live-explanation.md).

Живой проект содержит `story.vstory`, `story.json`, `story-project.json` и `scene-runtime.json` с pin на точный выпуск. Manifest владеет entry, авторскими model/subject-модулями и ресурсами; конкурирующие entry отвергаются. Готовый приём использует собранную страницу без npm и компиляции. Для собственного JS/TS собираются авторские модули, общий 2D runtime переиспользуется. Браузерная подготовка проверяет candidate до записи. Переносимый исходный архив замыкает зависимости при `story_produce`.

Для собственного JS/TS `story_create` без `document` и `example` создаёт нейтральный каркас без сеанса; `example: "gpt-model"` копирует эталон. Этот проект содержит lockfile и архив runtime; подготовка имеет job. Автор наполняет его, проверяет через `story_review` и показывает через `story_open`. Результат создания содержит файлы, entry, runtime и `sourceRevision`; повтор `requestId` возвращает исходную квитанцию. `story_help` принимает несколько запросов и читает API закреплённого пакета до первой успешной сборки. `story_inspect` может ограниченно ждать изменения job, до 15 секунд.

Публичный `context` связывает проект и сцену. Он сохраняется при restart и
проверяется до разбора ссылок; не принимает свежие данные молча. Исторический
повтор разрешается до проверки свежести. Внутри `sourceRevision` описывает рабочие входы; `buildRevision` — подготовленную редакцию; `shownSourceRevision` — источник подтверждённой сцены. Показанная A и рабочая B существуют явно. Одна транзакция `story_edit` создаёт один шаг undo. Семантическая операция и её отмена требуют готового живого сеанса: полная проверка, включая будущие подписи, выполняется до записи исходника. Ошибка сохраняет принятую редакцию; после записи ответ отдельно сообщает подтверждённый показ. При файловых изменениях запускается обычная подготовка; устаревшие автоматические задания заменяются свежими. Принятый `requestId` повторно не применяется. Внешние изменения проверяются перед записью и отменой.

При обычной сборке кандидат загружается на паузе. Перед переключением он получает checkpoint существующего renderer. Ревизия и generation меняются после подтверждения кандидата; ошибка оставляет предыдущее представление доступным. Семантическая правка готового приёма сохраняет iframe и generation, заменяя документ через тот же SceneHandle. `story_inspect(sessionId, file)` читает источник показанной сборки, `story_inspect(projectId, file)` — рабочий источник.

`story_review` и `story_produce` принимают общий адрес входа:

```js
const shown = { kind: 'build', context };
const working = { kind: 'working', context };
```

Вход фиксируется при постановке задания и сохраняется при отмене, retry и последующих правках. Результат сообщает фактически использованные версии. Агент явно выбирает показанную сборку или рабочую редакцию по запросу пользователя. Готовая сборка повторно использует свои ресурсы и звук.

HTML, PNG и поддерживаемый сценой SVG могут сохранить текущие условия. Видео требует явного выбора всего рассказа или интервала. Остальные форматы — SRT/VTT и архив редактируемого проекта. Существующий проект сохраняет runtime; `story_migrate` обновляет его явной отменяемой транзакцией.
Тихий выпуск (`silent:true`) исключает записи из HTML и звука видео при любом выбранном входе, сохраняя общий сценарий и исходную сборку. Для рабочих исходников этот выбор применяется до подготовки голоса; тихий HTML не загружает голосовые модели и кодировщик. Режим подготовки входит в квитанцию неизменяемого входа и сохраняется при retry.

Видео всегда выпускается в 16:9, по умолчанию 960×540. Общий `videoDimensions` обслуживает MCP, CLI и экспортёр: один размер определяет второй, округление идёт до единиц 32×18 px, доступный диапазон — 320×180…3840×2160. Явная пара другого соотношения отклоняется до очереди и подготовки ресурсов. Результат сообщает фактические размеры.

## Сессия и восстановление

Обычная карточка показывает сцену и её плеер. Служебный footer, кнопка настроек и ссылки на готовые файлы отсутствуют; настройки доступны через `story_preferences`, файлы — в результате задания. Агент согласовывает озвучку в чате и вызывает `story_voice` только по желанию пользователя; выпуск выполняет через `story_produce`. Возврат к уроку и показ подготовленной правки появляются под сценой только по ситуации. Карточка и развёрнутое представление хоста используют одну сессию. Ручное действие отменяет запоздалое управление. Управляющий набор проверяет ревизию, возможности и `requestId`; ошибка сообщает завершённый префикс. Неопределённо выполненные команды автоматически не повторяются.

После потери связи панель держит кадр и приостанавливает воспроизведение. В течение 15 секунд она пробует восстановить существующую сессию, проверяя владельца и generation; затем показывает ручное восстановление. Успешное восстановление остаётся на паузе. Дополнительный пример открывается с возвратом к предыдущему объяснению.

Краткое наблюдение заменяет одно вложение контекста без нового хода агента. Полная модель, геометрия и исходники читаются по запросу. ACK `rendered` подтверждает подготовку и возможность перерисовки; при приостановленном хостом RAF возвращается `prepared`. Пиксельная проверка выполняется отдельно.
Наблюдение берёт время, условия и `presentedCue` из подтверждённого кадра. `cue` принятого запроса остаётся в инспекции для управления после ошибки подготовки.
Рисунок имеет пропорции 16:9; единственный плеер находится под ним вне масштаба композиции. В чате и боковой панели виден целый кадр. Разворачивание выполняет штатная кнопка карточки Codex; сцена не создаёт собственного увеличения или дублирующих кнопок. Фактический displayMode остаётся у MCP-оболочки. Переход сохраняет условия и позицию рассказа, без переноса фокуса и запуска воспроизведения.

## Установка и тяжёлые возможности

Начальная платформа — macOS 13.5+ Apple Silicon. Node/npm, каталог и авторский инструмент входят в комплект. [Установщик](../plugin/INSTALL.md) копирует выпуск в постоянный каталог, атомарно переключает `current` и регистрирует стабильный launcher. Процесс работает из физического каталога своего выпуска; удаление кэша Codex и переключение версии не меняют его рабочие файлы. После переподключения MCP смена единственного runtime ожидает завершения очереди (`RUNTIME_UPDATE_PENDING`); старые подключения затем возвращают `RUNTIME_UPDATE_REQUIRED` до собственного переподключения. Переход с выпусков до 0.13.0 отдельно описан в инструкции установки.

Собственный JS/TS-проект и дополнительные зависимости используют обычную установку npm; готовый живой приём сразу использует закреплённый установленный выпуск. Видео лениво готовит Chromium/FFmpeg. Higgs готовит управляемый Python и закреплённые модели: ориентир 12 ГБ загрузок, 18 ГБ свободного места, 32 ГБ рекомендуемой памяти. Очередь показывает этап и прогресс, отменяет работу и повторно использует проверенные части. Doctor не загружает ресурсы. Другую локальную модель или API агент подключает через [адаптер проекта](../skills/visual-explainer/references/voice-adapter.md); ключи остаются в окружении процесса. Плагин проверяет WAV, акустические метки и актуальность сценария до публикации. Музыка готовится при использовании в Higgs.

`StoryDocument` принадлежит `/story`: главы, реплики, тихое время и синхронизация речи. `IllustratedStory` собирает его поверх `SceneStory`. Персонажная глава приходит из `/characters`; её набор содержит редактируемые glTF, клипы и SVG. Условия сторонних компонентов перечислены в [THIRD_PARTY](../THIRD_PARTY.md).

## Приёмка

После законченного среза: `npm run build`, `npm run check`, затем проверки затронутых моделей и реальных сценариев на свежих `dist/` и `site/`.

Для живого маршрута проверяются предварительный содержательный кадр → подтверждённый документ в том же handle, ошибочная операция без записи, повтор исходной квитанции после следующей правки, undo, восстановление и выпуск закреплённой редакции. Время до первого содержания и время до подтверждённого результата измеряются отдельно; `prepared` без `rendered` не подтверждает задержку до изображения. Локальный MCP-сценарий и нативная карточка Codex учитываются раздельно.

Обязательные переходы: быстрый ввод/отмена/ошибка/retry; показанная A и рабочая B при выпуске; потеря связи и перезапуск; формула/происхождение/обратный seek; контакты персонажей и интерактивная схема; тихий урок и отменяемая подготовка голоса. На поверхности проверяются узкая ширина, обе темы, клавиатура и reduced motion, десять переходов чат → панель → чат и внешнее закрытие панели. Плеер проверяется отдельно от кадра: области нажатия от 44 CSS px, текст от 16 CSS px, шкала, время и скорость доступны при переносе элементов. Цели p95: ввод → изображение ≤100 мс, локальная команда → показ ≤250 мс, отдельно от LLM и первой подготовки.

Из установленного комплекта агент создаёт новое объяснение другой темы через публичный API; схема, математика, график, опыт и постановка сохраняются как возможности библиотеки. Фиксируются время, ошибки и служебные действия. Ручной поиск внутренних путей, установка зависимостей и повторное создание общих компонентов считаются дефектами.

Полная готовность требует живой карточки Codex, прослушивания готовой речи и самостоятельного прохода нового пользователя на другом поддерживаемом Mac: установить → создать → исследовать → править → выпустить → открыть перенесённый проект. Текущие результаты и открытая приёмка — в [аудите](authoring-audit.md).
