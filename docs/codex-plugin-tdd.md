# Visual Storytelling · Codex Plugin

Технический дизайн и состояние реализации на 5 октября 2026. Core 0.13, локальный плагин 0.3. TDD означает Technical Design Document.

## Продукт

Разговор становится редактируемым визуальным объяснением. Пользователь смотрит рассказ, исследует условия, задаёт вопрос о текущем кадре, получает правку и выпускает результат. Вычисления, просмотр и экспорт выполняются локально. Sites и собственный облачный backend сейчас не нужны.

Интерактив открывается в сообщении или развёрнутой панели. Одна активная сессия владеет воспроизведением; переход между представлениями сохраняет место, условия, выбор, камеру, звук и скорость. Ручное действие прерывает устаревшее управление агента. После переподключения сцена восстанавливается на паузе.

Чат остаётся местом обсуждения. Кнопки «Обсудить», отдельного поля сообщения и автосообщений из сцены нет. Текущий кадр прикрепляется одним заменяемым контекстом: IDs проекта/сессии/ревизии, момент, cue, до четырёх выбранных предметов и до восьми параметров. Бюджет содержательной части — 1500 символов. Повторные состояния не отправляются; изменения объединяются с задержкой 120 мс. При воспроизведении наблюдение обновляется раз в секунду. Геометрия, полная временная шкала и исходники запрашиваются инструментами. Закрытие снимает контекст; удалённое пользователем вложение самостоятельно не возвращается.

## Проект, просмотр и правка

Редактируемый проект — обычная директория с `story.vstory`, исходниками, ресурсами, lockfile и архивом закреплённой библиотеки. Код сцены остаётся предметной моделью: новый декларативный язык не вводится. Пользовательские проекты и выпуски сохраняются после удаления плагина. Индексы и сеансы лежат в `~/Library/Application Support/Visual Storytelling`.

`sourceRevision` хеширует авторские входы, включая зависимости и ресурсы. Производные каталоги и секреты исключаются. Внутренние символьные ссылки проверяются; выход за границу проекта и циклы запрещены. `buildRevision` связывает проект, исходную ревизию, название и собранный HTML. Состояние показанной сборки отделено от рабочей директории.

Файловая правка принимает ожидаемую ревизию и `requestId`. Проверка выполняется до записи каждого файла и после транзакции; внешняя правка не затирается. Журнал позволяет восстановить прерванную запись. Одна принятая правка — один шаг отмены. Повтор запроса возвращает прежний результат. Отмена проверяет актуальность файлов и сохраняет внешние изменения.

Сборка читает неизменяемый снимок. Зависимости устанавливаются через `npm ci --ignore-scripts` и переиспользуются по lockfile, архивам и платформе. Watcher собирает обычные файловые правки после стабилизации. Экспорт читает собственный снимок и не блокирует дальнейшее авторство.

Кандидат сначала загружается на паузе в изолированном renderer. Предыдущая версия продолжает работать. На паузе готовая правка применяется автоматически; во время рассказа доступно «Показать правку». Перенос использует свежую точку старой сцены, включая последние ручные действия. Ошибочная или устаревшая сборка не вытесняет рабочую.

Контрольная точка содержит cue + progress, числовое время, параметры, режим, выделение, логическую камеру, mute и rate. Cue позволяет сохранить смысловое место при изменении длительности. Если cue исчез, текущая реализация ограничивает числовое время новой длительностью; уведомление и выбор ближайшей главы ещё предстоят.

Временный эксперимент не меняет авторский код. `SceneHistory` группирует жест и даёт undo/redo; `ProjectStore` отменяет файловые правки. Сохранение понравившегося условия агент выполняет обычной правкой исходника. Восстановление представления не создаёт шагов истории.

## Agent DX

| Инструмент      | Результат                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `story_open`    | Открыть пример, путь проекта или прежнюю сессию в одном MCP App                                      |
| `story_create`  | Создать редактируемую работу из основы; вернуть пути, IDs и задание                                  |
| `story_inspect` | Компактное состояние, файл проекта, подробная модель/шкала/геометрия или job                         |
| `story_find`    | Найти cue по словам действия, рассказа или ID                                                        |
| `story_control` | Пауза, воспроизведение, cue/seek, режим, параметры, выбор, камера, mute/rate, undo/redo эксперимента |
| `story_edit`    | Сохранить или отменить одну файловую транзакцию и подготовить правку                                 |
| `story_produce` | Выпустить HTML, MP4, субтитры или архив редактируемого проекта                                       |
| `story_cancel`  | Остановить задание с освобождением worker                                                            |
| `story_help`    | Проекты, пять поставляемых основ или точное объявление API                                           |

`story_view` виден только приложению и обслуживает его подключение. Обычные inspect/control не создают карточек UI. Агент использует IDs из текущего контекста и получает детали только для конкретного вопроса.

Команда проверяет build/state revision и уникальность requestId перед выполнением. ACK означает два прошедших кадра renderer; окончание перехода и качество картинки этим не подменяются. Ручной ввод меняет ревизию и отменяет запоздалую команду. Потерянное представление не накапливает очередь управления.

Семантические предметы объявляются у рисуемых объектов: ID, имя, значение, единицы, исходник и причинные входы. SVG поддерживает выбор мышью/клавиатурой. Пространственные сцены используют общий транспорт и камеру; семантический raycast-выбор 3D ещё предстоит. Поиск сейчас текстовый по cue; расширение на названия предметов и предметный граф следует делать у существующих владельцев.

## Нативная интеграция

Portable `plugin.json` + `mcp.json`, навык и SDK MCP Apps образуют один комплект. STDIO запускает поставляемый Node через `./runtime/node`; формат `${PLUGIN_ROOT}/…` в поле `command` загрузчик Agent Plugins отклоняет. Аргументы и cwd используют `${PLUGIN_ROOT}`.

Разные STDIO-клиенты подключаются к одному runtime через Unix socket с правами 0600. Каталог данных имеет права 0700. Поколение renderer, подтверждённая остановка и короткая lease предотвращают одновременное управление. Runtime закрывается после ухода клиентов и завершения jobs. Совместимость установленной сборки проверяется при подключении.

UI использует MCP Apps bridge, OpenAI Extensions, inline/fullscreen и global/thread entrypoints. Авторский JavaScript исполняется в opaque sandbox iframe с `allow-scripts`; привилегированный SDK и файловые полномочия хоста туда не передаются. Страница включает локальные ресурсы; внешний сетевой доступ renderer не требуется. Версия и хеш UI входят в URI ресурса.

[Контракт UI](https://developers.openai.com/plugins/build/chatgpt-ui), [Extensions](https://developers.openai.com/plugins/build/extensions) и [Model-App Context](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#uiupdate-model-context-extensions) задают интеграцию. Проверка browser-host с реальным SDK подтверждает протокол и renderer. Нативный Codex отдельно принимает загрузку, вложенный sandbox, входы из интерфейса, смену режима и обратный контекст. Проверку браузера нельзя засчитать за этот этап.

## Звук и выпуск

Тихие объяснения работают сразу. Mute сохраняет положение; скорость 0.25–3× управляет общими часами. Подготовленная авторская дорожка может оставаться частью сцены; `silent` у выпуска позволяет исключить звук. Плагин не запускает синтез при обычном просмотре или экспорте. В репозитории сохраняется существующий локальный путь озвучки; публичный профиль не содержит Higgs, моделей и коммерчески ограниченных персонажей.

Локальный синтез, выбор провайдера и проверка готовности требуют отдельного законченного среза. Для Higgs сначала нужны подходящие права на предоставление модели через продукт. Голос Codex как разговор не равен API получения аудиодорожки: такой API здесь не реализован. Голосовое управление сценой нужно проверить в живом разговоре.

Job хранит состояние queued/running/succeeded/failed/cancelled/interrupted, реальные этапы, ограниченный лог и результат. Отмена доводится до остановки worker; перезапуск не объявляет незавершённый экспорт успешным. Повтор requestId не создаёт вторую работу.

HTML работает автономно, MP4 использует тот же renderer и время. Видео требует Chromium и FFmpeg на машине. Source-архив включает исходники, ресурсы и закреплённую зависимость. Готовый выпуск публикуется целиком после проверки неизменности входов.

## Проверка и следующие срезы

Проверки привязаны к границам: SceneHandle/история; два реальных STDIO-клиента и восстановление; изолированный MCP App; создание → правка → отмена → выпуск из устанавливаемого комплекта. Проверяются чужая ревизия, быстрые команды, ручной приоритет, отмена, восстановление и удаление контекста. Сборка и typecheck обязательны после изменений библиотеки.

| Срез                 | Состояние / критерий завершения                                                                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S0 · канал Codex     | Реализованы MCP, изоляция, передача управления и context replacement. Нативная приёмка после исправления манифеста завершается отдельно                                 |
| S1 · просмотр        | Готовые SVG/3D примеры, библиотека проектов, общий плеер, камера и восстановление                                                                                       |
| S2 · агент и предмет | Работают управление, cue-поиск, SVG-выбор, значения и причинные входы; остаются 3D-выбор и расширенный поиск                                                            |
| S3 · авторство       | Создание, ревизии, транзакции, undo, внешний редактор и безопасная замена сцены реализованы                                                                             |
| S4 · выпуск          | Локальные jobs, отмена, HTML/MP4/source и сохранение проектов; чистая установка на чужой машине ещё нужна                                                               |
| S5 · голос           | Mute/rate и тихий путь реализованы; установка/смена разрешённого провайдера, синхронизация после новой речи и живой голосовой сценарий остаются                         |
| S6 · публичная бета  | Нужны внешний пользовательский прогон, file entrypoint, ограничение размера кэша, доводка восстановления удалённых cue и согласованный канал публичного распространения |

Эталонный приёмочный сценарий: установить без нашей помощи → открыть пример в чате → развернуть → остановить голосом → выбрать предмет → изменить условие → обсудить происхождение значения → исправить объяснение → отменить → продолжить → выпустить → открыть после обновления. Автор должен справляться самостоятельно; зритель — объяснять показанный механизм.

## Поставка и права

Первая локальная сборка предназначена для macOS Apple Silicon. Node/npm входят в установку; первая подготовка зависимостей проекта использует npm registry. Примеры и инструкция соответствуют поставляемому API. Перед обновлением runtime открытые представления закрываются и подключаются заново.

Авторский код и документация — [0BSD](../LICENSE). Зависимости сохраняют свои условия; [THIRD_PARTY.md](../THIRD_PARTY.md) и notices входят в поставку. Higgs backend, модели, Spine runtime и Chibi не включены в публичный профиль. Максимально открытая лицензия нашего кода не меняет права сторонних ресурсов.

Репозиторий публичен; local marketplace не означает публикацию в официальном каталоге. Условия локального MCP и коммерческих функций проверяются перед подачей. Платёжный слой появится после подтверждения спроса и доступного канала. Работы пользователя остаются у него независимо от будущей модели оплаты.
