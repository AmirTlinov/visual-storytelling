# Visual Storytelling · Codex Plugin

Technical Design Document, 5 октября 2026. Core 0.14, плагин 0.4. Исходные срезы S0–S6 сохраняют критерии приёмки; реализация и проверка в настоящем Codex учитываются отдельно.

## Продукт

Разговор становится редактируемым визуальным объяснением. Пользователь смотрит, исследует условия, задаёт вопрос о текущем кадре, меняет материал и выпускает результат. Просмотр, подготовка, речь и экспорт выполняются локально. Облачный backend и Sites для этого пути не нужны.

Один viewer работает внутри сообщения и в развёрнутом представлении. Переключение сохраняет место, условия, выбор, камеру, звук и скорость. Разные разговоры получают независимые сеансы; явный запуск истории останавливает другие активные истории. Ручное действие отменяет запоздалое управление. После переподключения сцена восстанавливается на паузе. Дополнительный пример открывается в том же пространстве с возвратом к прерванному уроку.

Чат остаётся местом обсуждения. Кнопки «Обсудить», поля сообщения и автосообщений из сцены нет. Кадр прикрепляется одним заменяемым контекстом: проект/сеанс/ревизия, момент, cue, до четырёх выбранных предметов и до восьми параметров. Бюджет содержательной части — 1500 символов. Повторные состояния пропускаются, изменения объединяются за 120 мс; при воспроизведении наблюдение обновляется раз в секунду. Это обновление вложения, без нового хода агента. Закрытие снимает контекст; удалённое пользователем вложение самостоятельно не возвращается. Геометрия, полная шкала и исходники читаются по запросу.

## Проект и правка

Проект — обычная директория: `story.vstory`, исходники, сценарий, ресурсы, lockfile и архив закреплённой библиотеки. Проекты и выпуски лежат вне кэша установки. Настройки пользователя хранятся отдельно; по умолчанию новые проекты создаются в `~/Library/Application Support/Visual Storytelling/projects`.

`sourceRevision` хеширует авторские входы и зависимости; производные каталоги и секреты исключаются. Символьные ссылки проверяются: выход за проект и циклы запрещены. `buildRevision` идентифицирует исходную ревизию и собранный HTML с медиа. Показанная сборка и рабочие файлы имеют отдельные ревизии. Копия проекта получает новый ID; перенос привязывается к проверенному manifest.

Правка принимает ожидаемую ревизию и `requestId`. Проверки до записи каждого файла и после транзакции сохраняют внешние изменения; журнал восстанавливает прерванную запись. Одна принятая правка — один шаг отмены. Повтор запроса возвращает прежний результат. Временный эксперимент использует `SceneHistory`; сохранение условия выполняется правкой предметного исходника.

Создание сначала готовит полную директорию и публикует её целиком. Сборка читает неизменяемый снимок. Зависимости устанавливаются через `npm ci --ignore-scripts` и переиспользуются по lockfile, архивам и платформе. Watcher собирает обычные файловые правки после стабилизации. Экспорт читает собственный снимок и не блокирует авторство.

Кандидат загружается на паузе в отдельном изолированном renderer. Предыдущая версия остаётся доступной. На паузе готовая правка применяется автоматически; во время рассказа доступно «Показать правку». Передача переносит свежий checkpoint и приватное состояние, включая действия после подготовки кандидата. Ошибочная или устаревшая сборка не вытесняет рабочую.

Checkpoint содержит cue/progress, время, текущую главу и порядок глав, параметры, режим, выбор, логическую камеру, mute/rate. Исчезнувший cue возвращает к ближайшей сохранившейся главе с уведомлением. Удалённые предметы, несовместимые параметры и камера явно отражаются в `restoreNotices`; восстановление не создаёт шагов истории.

Pinned 0.9 открывается через адаптацию его наблюдаемых возможностей, сохраняя библиотеку проекта. Доступны позиция и прежние команды. Старая библиотека не предоставляет общего разрешения ручного запуска, полного checkpoint камеры/условий и иногда наблюдения playing; UI и inspect показывают эти ограничения. `story_migrate` отдельно проверяет новую сборку, затем одной отменяемой транзакцией меняет package/lockfile и добавляет архив новой библиотеки. Предыдущий архив сохраняется для undo.

## Agent DX

| Инструмент                    | Назначение                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| `story_open`, `story_create`  | Открыть работу/пример или создать проект из поставляемой основы                        |
| `story_navigate`              | Перейти к поясняющему примеру в текущей панели и вернуться                             |
| `story_inspect`               | Состояние, возможности, модель, шкала, геометрия, файл проекта или job                 |
| `story_find`                  | Ранжированный поиск cue, глав и предметов по тексту, заголовку, имени или ID           |
| `story_control`               | Пауза/play, cue/seek, режим, условия, выбор, камера, mute/rate, undo/redo эксперимента |
| `story_edit`, `story_migrate` | Отменяемая правка содержания или явное обновление закреплённой библиотеки              |
| `story_voice`                 | Доступные местные голоса, включение/смена/отключение синтеза                           |
| `story_produce`               | HTML, MP4, SRT/VTT и архив редактируемого проекта                                      |
| `story_cancel`, `story_retry` | Остановить подготовку и продолжить с проверенных этапов                                |
| `story_help`                  | Проекты, основы и точный API; с projectId — из закреплённой зависимости                |
| `story_preferences`           | Папка новых работ, язык/голос по умолчанию и бюджет кэша                               |

`story_view` — закрытый для модели канал приложения. Обычные команды не создают карточек. Набор управления проверяет ревизии и requestId до исполнения; простая пауза прерывает ожидающий запуск без предварительного inspect. ACK означает два кадра renderer, отдельно от окончания анимации. Ошибки ревизий возвращают code/current/action. Длинный лог и полная модель не входят в фоновое вложение.

Семантический ID принадлежит объясняемому предмету. SVG-клик/клавиатура, 3D-raycast и доступная подпись обращаются к одному объекту. Его значение, единицы, source и причинные входы объявляются рядом с рисунком. MathMorph использует собственные IDs/origins частей. Поиск объединяет эти сведения с cue и главами, без отдельной embedding-модели или второго предметного графа.

## Интеграция Codex

`plugin.json`, `mcp.json`, навык и MCP App поставляются вместе. STDIO запускает `./runtime/node`; аргументы и cwd используют `${PLUGIN_ROOT}`. Разные STDIO-клиенты соединяются с одним процессом по требованию через Unix socket 0600 в каталоге 0700. После ухода клиентов и завершения jobs процесс закрывается. Discovery и UI доступны до подключения runtime; конфликт версий возвращает понятную ошибку операции с повтором после переподключения.

UI объявляет inline/fullscreen, global/thread, file и settings entrypoints. `story.vstory` читается через host resources: локальный file URI открывает папку, opaque URI разрешается только в уже зарегистрированный проект. Один manifest без доступной папки не выдаётся за полный переносимый проект. Для переноса предназначен source-архив.

Авторский JavaScript исполняется в opaque iframe `allow-scripts`. Привилегированный SDK и файловые полномочия туда не передаются. HTML включает ресурсы; внешняя сеть renderer не требуется. Версия и хеш UI входят в URI. Поколение, подтверждённая остановка и ограниченная lease защищают передачу управления. Компактный вид подстраивается под высоту содержимого, сохраняя доступность плеера. Подключение и ошибки имеют конечный видимый статус.

[UI contract](https://developers.openai.com/plugins/build/chatgpt-ui), [Extensions](https://developers.openai.com/plugins/build/extensions) и [Model-App Context](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#uiupdate-model-context-extensions) определяют протокол. Реальный SDK в browser-host проверяет его исполнение. Загрузка app-server, нативный iframe, entrypoints и живой голос Codex принимаются отдельно в приложении.

## Речь, подготовка и выпуск

Тихий путь доступен сразу. Mute мгновенно меняет слышимость, сохраняя часы; rate 0.25–3× управляет общим транспортом. Кнопка «Голос» меняет авторский выбор синтеза, сохраняя сценарий.

Поставляемый провайдер использует установленные голоса macOS через AVSpeechSynthesizer; компилятор и модели пользователю не нужны. Doctor перечисляет доступное без загрузок. Реплика синтезируется целиком; кэш учитывает текст, голос, темп, версию бинарника и macOS. Правка одной реплики повторно использует остальные. Нативные одинаковые временные метки сохраняются как группа слов, без выдуманного разделения; cue IDs остаются прежними. Audio и timeline входят в один кандидат и один выпуск. Музыкальное сведение этому провайдеру не заявлено.

Higgs остаётся отдельным локальным инструментом репозитория; в распространяемом профиле его нет. Подключение требует прав на предоставление модели через продукт. Голос Codex используется как канал разговора; получение его аудиодорожки и speech events здесь не объявлены. Живое управление принимается настоящим разговором.

Job хранит входную ревизию, параметры, реальные этапы, ограниченный лог и результат. Состояния: queued/running/succeeded/failed/cancelled/interrupted. Отмена завершается после остановки worker. Retry использует сохранённый снимок, зависимости и речь; недописанное видео пересчитывается. Если старые входы уже недоступны, используется только совпадающая исходная ревизия либо возвращается явная ошибка. Закрытие просмотра не отменяет экспорт.

Первое видео подготавливает закреплённые Chromium и FFmpeg, проверяя SHA-256 загрузки и бинарника. Локальный video renderer использует те же сцену и часы; FFmpeg кодирует через VideoToolbox. Прогресс показывает действующий этап. HTML автономен; исходный архив содержит ресурсы, сценарий, lockfile и runtime. Выпуск публикуется целиком.

GC ограничивает удаляемую подготовку бюджетом пользователя. Активные и сохранённые представления, текущие проектные сборки и доступные для retry снимки защищены. Защищённые данные могут превышать бюджет; исходники, история и выпуски вообще не относятся к этому кэшу.

## Срезы и приёмка

| Исходный срез                     | Реализованный путь                                                                                       | Оставшаяся приёмка                                                                               |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| S0 · нативный проход              | MCP, opaque renderer, управление существующим кадром, remount, context replacement                       | Полный inline/fullscreen проход в настоящем Codex после установки текущего комплекта             |
| S1 · установка и первое авторство | Архив с Node/npm; тихий create/build, готовые основы, help, настройки, cancel/retry                      | Самостоятельная установка на другом Mac                                                          |
| S2 · живое исследование           | SVG/3D выбор, provenance, поиск, ручной приоритет, независимые сеансы, дополнительный пример/возврат     | Настоящий разговор с voice Codex; оценка понятности зрителем                                     |
| S3 · надёжная правка              | Транзакции/undo, watcher, кандидат, удалённые cue, старый pinned handle, отменяемая миграция             | Нативный пользовательский проход с выбранным моментом                                            |
| S4 · возвращение и выпуск         | Sidebar/file/settings contract, повторное открытие, HTML/MP4/captions/source, перенос, повтор подготовки | File/sidebar через настоящий интерфейс Codex, перенос на другой компьютер                        |
| S5 · опциональный голос           | Разрешённый системный провайдер, выбор голоса, кэш реплик, cue IDs, синхронные выпуски                   | Прослушивание и оценка пользователями разных голосов/материалов                                  |
| S6 · внешняя бета                 | Комплект, инструкция, notices, поддержка, локальные проверки                                             | Другой человек проходит путь без сопровождения; согласованный публичный канал и документы подачи |

Технические проверки: `scene-completion`, `plugin-session`, `plugin-runtime`, `plugin-ui`, `plugin-completion`, `system-narration`, `plugin-authoring`. Последний запускает поставляемые runtime/server и проходит создание → правка/undo → речь → правка реплики → отмена/повтор выпуска → HTML/MP4/SRT/source → открытие перенесённого проекта через host resource. Проверка browser-host не засчитывается за нативный UX.

Эталонный пользовательский проход остаётся целым: установить → открыть в чате → развернуть → остановить голосом → выбрать предмет → изменить условие → обсудить происхождение → исправить/отменить → открыть пояснение/вернуться → выпустить → продолжить после обновления. Автор справляется самостоятельно; зритель объясняет механизм и предсказывает изменение условия. Цели p95 input→pixels 100 мс и локальная команда→показ 250 мс принимаются измерениями на фиксированной сцене/машине, отдельно от времени LLM и первой загрузки.

## Поставка и права

Профиль 0.4 рассчитан на macOS 13+ Apple Silicon. Сборка создаёт `.plugin-release` и `artifacts/plugin/visual-storytelling-VERSION-darwin-arm64.tar.gz` с SHA-256 и инструкцией. Node/npm, API, примеры, навык и notices соответствуют одному комплекту. Первая подготовка проекта использует npm registry; первая подготовка видео — указанные в `environment.mjs` upstream-архивы.

Авторский код и документация — [0BSD](../LICENSE). [Сторонние компоненты](../THIRD_PARTY.md) сохраняют свои условия. Higgs, модели голоса, Spine/Chibi исключены из распространяемого профиля. Репозиторий публичен; локальный каталог не означает публикацию в официальном каталоге OpenAI. Внешняя бета требует проверки фактической установки, ОС, прав и канала распространения. Коммерческий и платёжный слой появляется после подтверждения спроса и доступного механизма платформы.
