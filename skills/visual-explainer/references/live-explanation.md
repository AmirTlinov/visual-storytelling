# Один документ: рисунок, опыт и рассказ

Для деления на целые группы передай в `story_create` название проекта, новый
`requestId` и `document: {model: {kind: "division", count, divisor}}`.
Выбери числа под вопрос зрителя. Подготовленный приём поддерживает 0–36 предметов
и группы от 1 до 12: пустой набор, неполная группа и точное деление полноценны.

Короткий ввод нормализуется в `story.json`:

```json
{
  "version": 1,
  "models": [{ "id": "division", "kind": "division", "inputs": { "count": 17, "divisor": 5 } }],
  "views": [
    { "id": "groups", "kind": "groups", "model": "division" },
    { "id": "equation", "kind": "equation", "model": "division" }
  ],
  "chapters": [
    {
      "id": "division",
      "title": "Деление с остатком",
      "beats": [
        {
          "id": "gather",
          "say": "",
          "seconds": 1.2,
          "staging": { "model": "division", "operation": "gather" }
        },
        {
          "id": "group",
          "say": "",
          "seconds": 4,
          "staging": { "model": "division", "operation": "group" }
        },
        {
          "id": "remainder",
          "say": "",
          "seconds": 2.8,
          "staging": { "model": "division", "operation": "remainder", "focus": ["remainder"] }
        }
      ]
    }
  ]
}
```

`title` необязателен. Без собственной последовательности действует постановка
«предметы → полные группы → остаток». `chapters: []` в полном документе даёт
статический рисунок с исследованием: плеер и искусственные секунды отсутствуют.
ID модели, представления, главы и действия устойчивы при правках.

Модель хранит входы и вычисляет результат; `views` выбирают изображение.
`staging` связывает действие с моделью и направляет внимание. `action` и
`hold` — описания смысла для review. `text` появляется у рисунка;
`say` задаёт речь, пустая строка сохраняет действие тихим. Не называй остаток
до группировки и не дублируй вычисляемые количества в авторской фразе.

## Продолжение в той же карточке

В `story_edit` передай `projectId`, текущую `sourceRevision`, новый
`requestId` и цельный пакет `operations`:

```json
[{ "op": "set-inputs", "modelId": "division", "values": { "count": 20 } }]
```

`set-views` заменяет представления, `set-chapters` — последовательность глав.
Связанные ссылки меняются одним пакетом; проверка выполняется до записи.
Явно переданный вход заменяет соответствующее условие зрителя, даже если его
значение совпадает с исходником. Другие выбранные условия сохраняются.
Одна операция даёт один шаг undo.

Повтор использует тот же `requestId` и тот же вход. Он возобновляет доставку
без повторной записи; завершённый receipt остаётся историческим результатом.
Новая правка использует новую ревизию. Записанный исходник и показанный кадр
различаются в ответе: `shown` подтверждает согласованное наблюдение кадра,
`prepared` и frame opportunity не подтверждают проверенные пиксели или движение.

Проверь исходный результат и существенную границу, например 19 → 20 → 21 при
группе из пяти. `story_control` с `parameters` меняет вход зрителя;
`cue` перематывает рассказ. `detail: "model"` возвращает проверяемые числа
сразу в ответе действия. Дополнительный inspect нужен для углубления.
Рисунок, равенство и перемотка используют одну модель.

`presentationMetrics.first/current` сохраняют интервалы подготовки и
frame opportunity с привязкой к renderer, generation и timeOrigin.
Замер от запроса включает работу агента; отдельно открывай настоящий кадр
и проверяй непрерывное движение.

## JS/TS и сохранённые проекты

`normalizeStoryDocument` раскрывает короткий ввод; `validateStoryDocument`
проверяет полный документ версии 1; `editStoryDocument` применяет чистые
операции. `mountStoryDocument(root, document)` использует существующие
SceneShell и Story. `root.scene.authoring` даёт принятый документ,
проверку и замену на том же handle.

Рассказ с собственными главами подключает их фабрики через
`IllustratedStory`; его `models: []` и `views: []` сохраняют предметную
модель в обычном JS/TS-модуле представления. Такой проект готовится общим
сборщиком исходников. Подготовленный MCP-путь пока рисует встроенный division;
новый предметный модуль подключается через редактируемый исходный проект.

Старый проект продолжает использовать закреплённую библиотеку.
`story_migrate` преобразует прежний документ на кандидате и публикует
исходники вместе с pin после проверки. Пользовательские проекты сами
не обновляются. Голос, HTML, исходный архив и MP4 готовятся операциями выпуска.
