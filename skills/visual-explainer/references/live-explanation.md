# Короткий живой опыт

Для маршрута заказа:

```json
{
  "recipe": "dependency-route",
  "inputs": { "orderId": "417", "reserve": "shared", "disabled-provider": true }
}
```

Модель `route` связывает `dependency-network` и `order-status`. Заказ останавливается
у провайдера А; `reserve:"independent"` ведёт через Б. `none` выключает резерв.
`disabled-<nodeId>` задаёт отказ; ID узлов: shop, gateway, backup, provider,
independent, bank. Это учебная топология, а не инфраструктура реальной компании.
Приём даёт шестисекундный проход с сохранением ID заказа; `chapters:[]` — статический опыт.
Операции `disable-<nodeId>`, `enable-<nodeId>`, `reconnect-none/shared/independent`,
`reset`, `trace`, `finish` принадлежат обычной модели. Перемотка чисто повторяет
операции от авторских входов. В исследовании условия зрителя задают новый trace.
Для иной сети используй [авторский модуль](document-modules.md).

Используй один `StoryDocument` v2 для статического опыта и рассказа. Для целых
групп с остатком передай в `story_create.document` компактный вход:

```json
{ "recipe": "division", "inputs": { "count": 17, "divisor": 5 } }
```

Подбери небольшой пример под вопрос зрителя. Runtime, рисунок, шрифты и управление
уже собраны. Приём нормализуется в `story.json`: `version: 2`, `models`, `views`,
`chapters`. Модель по умолчанию имеет ID `division`; её представления — `groups`
и `equation`. Сохранённый документ и ответы используют окончательные ID.
Рисунок поддерживает 0–36 предметов и размер группы 1–12; ограничения принадлежат
предметной модели. Ноль, неполная группа и точное деление — полноценные состояния.

Без `chapters` компактный приём даёт восьмисекундный рассказ: предметы собираются
в полные группы, остаток выделяется, появляется равенство. `chapters: []` создаёт
настоящий статический опыт без времени, play и seek. В каноническом документе
отсутствующие главы нормализуются в пустой список.

Собственные главы нужны для конкретной содержательной задачи. Действие указывает
обычную чистую JS-операцию зарегистрированной модели; описание `action` остаётся
авторской заметкой. Не называй остаток до группировки. Например:

```json
{
  "recipe": "division",
  "inputs": { "count": 17, "divisor": 5 },
  "chapters": [
    {
      "id": "experience",
      "title": "Проверяем остаток",
      "beats": [
        { "id": "collect", "operation": { "model": "division", "name": "group" }, "seconds": 4 },
        {
          "id": "notice",
          "focus": ["division:remainder"],
          "hold": "Время для собственного прогноза",
          "seconds": 3
        }
      ]
    }
  ]
}
```

`text` необязателен: короткая естественная реплика помогает заметить причину у
рисунка. Формулу и числа вычисляет модель; не дублируй их в авторском тексте.
Метки рассказа имеют ID `experience.gather`, `experience.group`,
`experience.remainder`; сохраняй ID при правках.

Если карточка уже открыта, передай её `context` в `story_create`: опыт появится
в ней, прежний останется доступен через «Назад». Это работает для подготовленного
документа; собственный JS/TS и копия GPT проходят обычную сборку. Ответ различает
сохранённый исходник и доставку: `pending`, `prepared`, `shown`, `failed`.
Повтори тот же `requestId` и исходные аргументы для незавершённой доставки.
Завершённый receipt остаётся историческим результатом. Сохраняй исходные
аргументы повтора, включая context. Новая операция проверяет его исходник;
управление также проверяет наблюдённое состояние и поколение renderer.

Продолжай через `story_edit` с `context` из предыдущего результата, новым
`requestId` и `operations`:

```json
[{ "op": "set-inputs", "modelId": "division", "values": { "count": 20 } }]
```

`set-views` заменяет представления, `set-chapters` — главы. Весь пакет и итоговые
ссылки проверяются до публикации; ошибка сохраняет принятый кадр. Явно переданный
вход заменяет условие зрителя, остальные значения сохраняются. Повтор не пишет
исходник снова. Ответ содержит `publication`, существенную `difference` и следующий `context`.
После успеха продолжай с ним. `story_inspect` нужен для подробностей и конфликтов.

Правка JS/TS через `changes` сначала готовит неизменяемого кандидата. Пока job
выполняется, `project` описывает принятый исходник. После успеха новую ревизию
возвращает `job.result.project`; ошибка сборки сохраняет исходник, pin и кадр.
Миграция публикует уже проверенную сборку вместе с исходником и pin.

Проверь существенную границу: при группе из пяти — 19 → 20 → 21. Для ручного
входа используй `story_control` с командой `parameters`, `values:{count:20}` и
контекстом наблюдённой сцены. `detail:"model"` возвращает
вычисленные значения в том же ответе. Рисунок и формула сохраняют условия при
перемотке. Открой настоящий кадр: API не подтверждает читаемость и движение.

`presentationMetrics.first/current` описывают подготовку и frame opportunity.
Они дополняют замер от пользовательского запроса с работой агента; готовность
и кадровый ACK не являются доказательством пикселей или целевых 5/20 секунд.

В JS/TS тот же документ принимает `IllustratedStory.mount(root, {document})`.
`validateStoryDocument` и `editStoryDocument` принадлежат общей схеме; предметные
JS-модули владеют входами, операциями и научными ограничениями. Голос, HTML,
исходный архив и видео выпускаются существующими инструментами по необходимости.
Старый проект сохраняет свой pin. `story_migrate` явно преобразует legacy на копии,
проверяет новый документ и сборку, затем публикует исходник и pin одной транзакцией.
Изменённый пользовательский entry требует явной правки кода.
