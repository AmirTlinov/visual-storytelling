# Короткий живой опыт

Для опыта с рычагом:

```json
{
  "recipe": "lever",
  "inputs": { "leftForce": 4, "leftArm": 30, "rightForce": 3, "rightArm": 20 }
}
```

Грузы двигаются прямо на рисунке; стрелки клавиатуры меняют расстояние,
Shift ускоряет шаг. Кнопки −/+ меняют вес. Во время перетаскивания рычаг
удерживается горизонтально; отпускание запускает новый опыт из покоя.
Воспроизведение и повтор принадлежат общему плееру. Один жест — один шаг общей истории.

`Force` означает вес закреплённого груза в Н, `Arm` — расстояние вдоль
перекладины в см, оба целые0–100. Стартовые моменты вычисляются точно в Н·м.
Модель невесомой балки с точечными массами F/g вычисляет угол и скорость:
Iθ″=(Fл rл−Fп rп)cosθ. При наклоне перпендикулярное плечо равно r cosθ.
Видимые упоры ограничивают поворот до±18° и гасят скорость при контакте;
остановка на упоре отличается от равновесия грузов. Случай нулевой инерции
не вращается. [Механика вращения](https://openstax.org/books/university-physics-volume-1/pages/10-7-newtons-second-law-for-rotation).

Операция `release` воспроизводит две физические секунды; по умолчанию показ
замедлен втрое, затем следует двухсекундная пауза. Часы на рисунке
показывают время опыта; длительность cue и скорость player задают темп просмотра.
Новый input сбрасывает опыт к горизонтальному старту. Undo, restore и seek
сохраняют принятое время. Reduced motion сохраняет физическое время: это
предметное движение, без декоративного покачивания. `chapters:[]` показывает срез через2с без запуска.
Исходник: [рычаг](../../../tools/document-modules/lever/story.json).

Для явного контролируемого сравнения:

```json
{
  "recipe": "comparison",
  "kind": "lever",
  "inputs": { "leftForce": 10, "leftArm": 40, "rightForce": 10, "rightArm": 20 },
  "changes": { "rightForce": 20 }
}
```

Оба рисунка показывают независимые срезы через2с после горизонтального старта.
При движении сумма весов не равна фактической динамической реакции шарнира;
она остаётся лишь требуемой реакцией для вертикальной статики.

`comparison` меняет одну выбранную величину. Операции `baseline`, `change`,
`compare` последовательно раскрывают исходный и изменённый опыт за 6 секунд;
`chapters:[]` сразу показывает статическое сравнение. Оба рисунка используют
общую калибровку по двум снимкам. При ширине менее 766 CSS px контроль «Опыт»
переключает равные по размеру панели. Меню и история принадлежат прежнему shell.
Короткий `text` раскрывается у изменённого опыта; длинная реплика отклоняется
до публикации. Раздели её на последовательные действия.

Тот же приём для заказа:

```json
{
  "recipe": "comparison",
  "kind": "dependency-route",
  "inputs": { "orderId": "417", "reserve": "shared", "disabled-provider": true },
  "changes": { "reserve": "independent" }
}
```

Обе ветви сохраняют заказ и отказы остальных узлов. Независимый резерв
не исправляет отказ банка или собственного провайдера Б.
Исходники: [рычаг](../../../tools/document-modules/lever-comparison/story.json),
[заказ](../../../tools/document-modules/route-comparison/story.json).

Для сложения долей одного и того же целого:

```json
{
  "recipe": "fractions",
  "inputs": { "leftNumerator": 1, "leftDenominator": 2, "rightNumerator": 1, "rightDenominator": 3 }
}
```

Модель `fractions` связывает `fraction-parts` и `fraction-equation`. Шестисекундный
рассказ выравнивает целое, разделяет доли, переносит части и показывает 5/6.
`action:"copy"` сохраняет первую долю и создаёт её копию: сумма в приёмнике
остаётся 5/6, всё активное количество становится 4/3; `added` содержит добавленную 1/2.
`chapters:[]` даёт статический опыт. Числители лежат от 0 до знаменателя;
знаменатели рисунка — 1,2,3,4,6,8,12. Ноль и сумма больше одного поддерживаются.
Это границы композиции; точная арифметика использует сокращённые safe-integer
`{numerator,denominator}` и BigInt для промежуточных вычислений.

Операции `align`, `partition`, `collect`, `finish` идут однократно в этом порядке;
`finish` требует `collect`. Обратная перемотка повторяет рассказ с начала.
Каждая часть имеет `id`, точное `amount`, `unit`, `reference`, `container`,
`inputs` и исходные `origins`. Новый ID не переиспользует известное происхождение.
Перенос сохраняет ID и количество; копирование задаёт новый ID и `copiedFrom`.
Рисунок и формула представляют те же исходные ID, inspect раскрывает вклад частей.
Доли разных единичных целых нельзя складывать без отдельного измеримого преобразования.
[Запускаемый исходник](../../../tools/document-modules/fractions/story.json).

Для маршрута заказа:

```json
{
  "recipe": "dependency-route",
  "inputs": { "orderId": "417", "reserve": "shared", "disabled-provider": true }
}
```

Модель `route` связывает `dependency-network` и `order-status`. Заказ останавливается
у провайдера А; `reserve:"independent"` ведёт через Б. `none` выключает резерв.
`disabled-<nodeId>` задаёт отказ; ID узлов: shop, gateway, backup, provider,
independent, bank. Это учебная топология, а не инфраструктура реальной компании.
Приём даёт шестисекундный проход с сохранением ID заказа; `chapters:[]` — статический опыт.
Операции `disable-<nodeId>`, `enable-<nodeId>`, `reconnect-none/shared/independent`,
`reset`, `trace`, `finish`, `try-reserve` принадлежат обычной модели.
`try-reserve` начинает путь через включённый резервный вход; без резерва
он недостижим. Обычный trace выбирает рабочий маршрут автоматически. Перемотка чисто повторяет
операции от авторских входов. В исследовании условия зрителя задают новый trace.
Для иной сети используй [авторский модуль](document-modules.md).

Используй один `StoryDocument` v2 для статического опыта и рассказа. Для целых
групп с остатком передай в `story_create.document` компактный вход:

```json
{ "recipe": "division", "inputs": { "count": 17, "divisor": 5 } }
```

Подбери небольшой пример под вопрос зрителя. Runtime, рисунок, шрифты и управление
уже собраны. Приём нормализуется в `story.json`: `version: 2`, `models`, `views`,
`chapters`. Модель по умолчанию имеет ID `division`; её представления — `groups`
и `equation`. Сохранённый документ и ответы используют окончательные ID.
Рисунок поддерживает 0–36 предметов и размер группы 1–12; ограничения принадлежат
предметной модели. Ноль, неполная группа и точное деление — полноценные состояния.

Без `chapters` компактный приём даёт восьмисекундный рассказ: предметы собираются
в полные группы, остаток выделяется, появляется равенство. `chapters: []` создаёт
настоящий статический опыт без времени, play и seek. В каноническом документе
отсутствующие главы нормализуются в пустой список.

Собственные главы нужны для конкретной содержательной задачи. Действие указывает
обычную чистую JS-операцию зарегистрированной модели; описание `action` остаётся
авторской заметкой. Не называй остаток до группировки. Например:

```json
{
  "recipe": "division",
  "inputs": { "count": 17, "divisor": 5 },
  "chapters": [
    {
      "id": "experience",
      "title": "Проверяем остаток",
      "beats": [
        { "id": "collect", "operation": { "model": "division", "name": "group" }, "seconds": 4 },
        {
          "id": "notice",
          "focus": ["division:remainder"],
          "hold": "Время для собственного прогноза",
          "seconds": 3
        }
      ]
    }
  ]
}
```

`text` необязателен: короткая естественная реплика помогает заметить причину у
рисунка. Формулу и числа вычисляет модель; не дублируй их в авторском тексте.
Метки рассказа имеют ID `experience.gather`, `experience.group`,
`experience.remainder`; сохраняй ID при правках.

Если карточка уже открыта, передай её `context` в `story_create`: опыт появится
в ней, прежний останется доступен через «Назад». Это работает для подготовленного
документа; собственный JS/TS и копия GPT проходят обычную сборку. Ответ различает
сохранённый исходник и доставку: `pending`, `prepared`, `shown`, `failed`.
Повтори тот же `requestId` и исходные аргументы для незавершённой доставки.
Завершённый receipt остаётся историческим результатом. Сохраняй исходные
аргументы повтора, включая context. Новая операция проверяет его исходник;
управление также проверяет наблюдённое состояние и поколение renderer.

Продолжай через `story_edit` с `context` из предыдущего результата, новым
`requestId` и `operations`:

```json
[{ "op": "set-inputs", "modelId": "division", "values": { "count": 20 } }]
```

`set-views` заменяет представления, `set-chapters` — главы, `set-resources` — источники и границы данных. Весь пакет и итоговые
ссылки проверяются до публикации; ошибка сохраняет принятый кадр. Явно переданный
вход заменяет условие зрителя, остальные значения сохраняются. Повтор не пишет
исходник снова. Ответ содержит `publication`, существенную `difference` и следующий `context`.
После успеха продолжай с ним. `story_inspect` нужен для подробностей и конфликтов.

Правка JS/TS через `changes` сначала готовит неизменяемого кандидата. Пока job
выполняется, `project` описывает принятый исходник. После успеха новую ревизию
возвращает `job.result.project`; ошибка сборки сохраняет исходник, pin и кадр.
Миграция публикует уже проверенную сборку вместе с исходником и pin.

Проверь существенную границу: при группе из пяти — 19 → 20 → 21. Для ручного
входа используй `story_control` с командой `parameters`, `values:{count:20}` и
контекстом наблюдённой сцены. `detail:"model"` возвращает
вычисленные значения в том же ответе. Рисунок и формула сохраняют условия при
перемотке. Открой настоящий кадр: API не подтверждает читаемость и движение.

`presentationMetrics.first/current` описывают подготовку и frame opportunity.
Они дополняют замер от пользовательского запроса с работой агента; готовность
и кадровый ACK не являются доказательством пикселей или целевых 5/20 секунд.

В JS/TS тот же документ принимает `IllustratedStory.mount(root, {document})`.
`validateStoryDocument` и `editStoryDocument` принадлежат общей схеме; предметные
JS-модули владеют входами, операциями и научными ограничениями. Голос, HTML,
исходный архив и видео выпускаются существующими инструментами по необходимости.
Старый проект сохраняет свой pin. `story_migrate` явно преобразует legacy на копии,
проверяет новый документ и сборку, затем публикует исходник и pin одной транзакцией.
Изменённый пользовательский entry требует явной правки кода.

Нормировка вероятностей и отдельный опыт с выборкой используют [общий trace и ресурсы](probability.md).

Для непрерывной истории сохраняй один model ID и ID предмета во всех главах.
[Заказ417](../../../tools/document-modules/continuous-order/story.json) проходит
отправку, отказ А, неудачный общий резерв и независимый обход за26,5секунды.
Это учебная сеть. Действия принадлежат `dependency-route`; текст указывает,
что заметить сейчас, а статусы и маршруты вычисляет модель.

`chapter.views` выбирает ID из общего `document.views`; остальные представления
этой главы скрыты, модель продолжает предыдущие операции. `beat.focus` ссылается
на доступный предмет этой главы. В исследовании условия сохраняются при смене
главы; «Рассказ» возвращает авторский replay. `remove-order` оставляет явное
состояние `present:false`/`outcome:"removed"`, `restore-order` возвращает предмет.

Фабрика `IllustratedStory.chapters` получает авторскую длительность и script.
Её `render(frame)` читает `frame.subject.models`, `.views`, `.beat` и `.resources`:
там тот же `documentModelsAt`, что в подготовленном опыте. Не пересчитывай trace
в рисунке. Геометрию можно освобождать при выходе; следующий render восстановит
предмет из абсолютного replay. `ChapterFrame.chapter` задаёт выбранную главу,
включая исходящую сторону общей временной границы. Произвольный renderer должен
сам обеспечивать атомарность изменений своего уже активного кадра.

Для идеальной электрической цепи:

```json
{ "recipe": "circuit", "inputs": { "closed": false } }
```

За четыре секунды рисунок показывает разрыв и замыкание ключа. Ключ на схеме
доступен мышью и клавиатурой; условия и undo принадлежат общему shell.
`chapters:[]` создаёт статический опыт. Канонический модуль `circuit` имеет вход
`closed:boolean`, одно представление `kind:"circuit"` и операции `open`/`close`.
Семантические объекты — `<modelId>:switch` и `<modelId>:lamp`.
Это идеальная установившаяся модель: лампа работает при замкнутом контуре.
Она не вычисляет ток, сопротивление, яркость или переходный процесс. Синие
метки показывают условное направление тока; их скорость не изображает движение
электронов. Речь не требуется и автоматически не готовится.
[Условный ток и замкнутая цепь](https://openstax.org/books/university-physics-volume-2/pages/9-1-electrical-current);
[дрейф электронов](https://openstax.org/books/university-physics-volume-2/pages/9-2-model-of-conduction-in-metals).

Короткая авторская `text` по умолчанию относится к исходному рассказу. При ручном
изменении условия она скрывается; рисунок и вычисленные подписи продолжают
показывать новый опыт. После несовместимой правки исходных входов прежняя мысль
также не утверждается заново. Для общей инструкции, верной при любых условиях,
явно задай `speech:{id:"thought.try",when:{basis:"presented",models:[]}}`.
Для условного утверждения перечисли только его проверяемые входы в `when.models`.
Эта применимость относится к смыслу мысли; озвучка по-прежнему опциональна и
подготавливается только явно. `say:""` исключает подпись из голосового задания,
сохраняя её условия. Не объявляй фразу с числами или частным выводом общей.

Обычные captions и доступный текст проверяются по завершённому кадру независимо
от звука. SRT/VTT используют канонический рассказ. Условная мысль с
`basis:"presented"` исключается из переносимых субтитров целиком, если её модель
меняется операцией внутри этой мысли; живой опыт проверяет её на каждом кадре.
Разделяй такое объяснение на применимые мысли или показывай вычисляемую подпись.
Для сравнения маршрутов подготовленный рисунок использует кадр 4:3: подписи и
переключатель «Было/Стало» должны помещаться при узком окне без уменьшения букв.
