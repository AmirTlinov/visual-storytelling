# Новая сцена

Из каталога навыка:

```sh
node ../../tools/scene.mjs new /absolute/output/my-story --example explorer-svg
cd /absolute/output/my-story
npm install
npx visual-story api SceneShell.mount SceneOptions  # точный контракт установленного пакета
npm run build
npm run dev
```

Каталог должен быть пустым. Подбери основу через [каталог и CLI](authoring-guide.md#выбрать-пример); карточка CLI содержит кадр, исходник и команду создания.

`api NAME.member` показывает отдельный метод и его аргументы; `--full` раскрывает связанные объявления. `info` показывает фактический пакет и идентификатор сборки. Справка строится из установленных типов.

Сцена получает предметные исходники, готовые данные и версионированный tarball `@visual-storytelling/core`; `npm install` создаёт lockfile. Меняй содержание в этой папке. `npm run build` собирает `dist/`, `npm run dev` следит за исходником, пересобирает его и возвращает страницу к текущему времени; `npm run preview` показывает готовую сборку с перемоткой звука. Библиотека устанавливается зависимостью; её исходники и стили в сцену не копируются.

HTML/JS-сцена хранит композицию в `scene.js`. У примеров с генератором его запуск задан в `scene.json`: `build` и dev-сервер пишут SVG в `dist/`; редактируется генератор. Установленный пакет содержит каталог, исходники, превью, навык и документацию той же версии. Готовые WAV галереи в него не входят; сохранённый сценарий позволяет собрать голос после редактирования.

Для новой темы создавай тихую копию через `--no-audio` и редактируй `narration.json`.
В плагине голос включает `story_voice`; отдельный проект использует Higgs по умолчанию
или явно выбранный в `voice.json` провайдер, затем `npm run audio` и сборку. [Озвучка](narration.md) описывает
оба пути. `--silent` создаёт постоянную тихую сцену без речевых файлов, сохраняя
время, метки и авторские атрибуции. Общая оболочка — в [шаблоне](scene-template.md).

## Где что находится

[Карта владельцев](../../../docs/architecture.md) — общий источник для библиотеки и навыка.
`examples/ИМЯ/scene.js` или предметный генератор хранит модель, композицию и сценарий.
Пакет владеет общими материалами, временем, управлением и поверхностями.

Основной маршрут — `SceneShell.attachStory` из [законченного шаблона](scene-template.md).
Для собственной SVG-разметки принятых рассказов «Площадь» и «Остаток» `story` подключается
к общему `player`; `SmilPlayer` управляет временем встроенного SVG,
`StepPlayer` — дискретными шагами. Они используют общие часы и управление.

```js
import '@visual-storytelling/core/style.css';
import { SceneShell, SketchInk, SketchMotion, SvgLayout } from '@visual-storytelling/core';
import timing from './timeline.json' with { type: 'json' };
```

Для SVG-генератора импортируй `svgRange` и `fitSvgControls` из `@visual-storytelling/core/controls`, `SketchInk` — из `@visual-storytelling/core/ink`. Генератор встраивает производный код пакета. Общие исправления делай у владельца в библиотеке. Зависимость проекта обновляй через `story_migrate` в плагине или `visual-story update DIRECTORY --from LIBRARY`; команда закрепляет и проверяет runtime.

Прозрачный фон и чернила обеих тем заданы общим CSS; `appearance: "interface"` выбирает нейтральные элементы управления для продуктовой сцены, предметное оформление остаётся у её автора. Палитра `--ve-blue`, `--ve-orange`, `--ve-purple`, `--ve-green`, `--ve-red`, `--ve-yellow` выбирается по смыслу; `*-wash`/`*-soft` задают заливки. В SVG передавай цвет текста через `color`, рисунка — через `fill`/`stroke`. Сетка `.ve-scene` по умолчанию охватывает весь учебный лист, включая заголовок и нижний плеер; вложенный `surface` получает `grid: false`. Для измерительного SVG с камерой [шаблон](scene-template.md#один-путь-от-времени-к-рисунку) объясняет перенос сетки в координаты рисунка. После правки осевых букв или профилей пера пересобери три WOFF2 через `uv run tools/build_pencil_font.py` из корня библиотеки.

## Несколько представлений в одном рассказе

Для нескольких представлений используй `SceneStory` из `/story`. Глава владеет представлением через
`mount → render/capture/snapshot/dispose`; часы и параметры принадлежат общему Story.
Представления создаются по потребности: `render` восстанавливает кадр из времени
и общих параметров, `dispose` освобождает ресурсы. Прямой `scene.seek()` сопровождай
`await scene.ready?.()` перед захватом; команды инструмента и экспорт ожидают сами.
`inkChapter` сохраняет живой SVG, `areaDiagram` даёт готовую адаптивную композицию
измерения, `PhysicsReplay` перематывает физику. Контракты доступны через
`api SceneStory SceneChapter inkChapter physicsChapter`.

`character-lesson` соединяет `characterChapter` из `/characters`, математику
и физический опыт через общий `SceneStory`. `IllustratedStory` добавляет документ
с главами и речью; тихая разметка доступна до подготовки голоса.

В подготовленном мире меняй `arrange`, `cast` и `perform`. Отношения сохраняются
между вариантами. `portable` даёт письмо, чашку и прибор; своя SVG-иллюстрация задаёт
контакт захвата и кнопку один раз. `take`, `put`, `press`, места скамьи, дверь
с обеих сторон и маршруты используют те же контакты. [Постановка](../../../docs/characters.md).
Крупный план выбирает `hero.face`, `hero.hand-left` или предмет через `shot.focus`.

Перед выпуском проверяй `scene.presentation()` и реальные кадры на целевой ширине.
`unreadableText` измеряет экранный размер букв; `clipped` — видимую область.
`review DIST` получает эти данные от того же владельца, что и живая сцена.

## Компоновка

Дождись `SceneShell.ready()` перед измерением. Размещаемые подписи и предметы должны уже быть в SVG.
`SvgLayout.observe(svg, width => height)` сам ждёт шрифт, вызывает компоновку при
изменении ширины и выставляет `viewBox` и высоту. Возвращает `update()` и `dispose()`.
Для числовых операций `MathMorph2D/3D` сами выбирают ряды и читаемый масштаб. Монтируй 2D-компонент в отдельный HTML-контейнер: высота следует его содержимому. Для собственных предметных сцен используй общие измерения и размещение ниже.
`node(drawing, id, value, options)` владеет контуром и ограниченной им надписью; `node.value()` обновляет оба. `lettering` с `bounds` центрирует реальные штрихи внутри уже заданного прямоугольника или эллипса.
В задачах на измерение фигура и сетка используют одну единицу, шаг и начало координат:
для тетрадной клетки 5 мм это 1 см = 2 клетки и 1 см² = 2×2 клетки.
`--ve-grid-step`, `--ve-grid-x`, `--ve-grid-y` задают шаг
и начало фоновой сетки в CSS-пикселях относительно её контейнера. По умолчанию шаг — 20 px, усиленная линия повторяется через пять клеток. Масштабируй
фон и фигуру вместе; совмещай контуры с линиями, сохраняй сетку под заливкой.
Изменение параметров фигуры сохраняет начало и шаг сетки; пересчитывай их только при изменении размера области или явном масштабировании.
Центрируй изменяемую фигуру привязкой её края к ближайшей линии неподвижной сетки.

```js
const { element, place, row, beside, connect, along, observe } = SvgLayout;
const label = element('text', {}, 'Результат');
svg.append(label);
place(label, 200, 80); // центр измеренной надписи
row([a, plus, b], { x: 200, y: 140, gap: 12 });
beside(label, object, { side: 'bottom', gap: 10 });
const route = connect(leftCircle, rightCircle, {
  fromShape: 'ellipse',
  toShape: 'ellipse',
  gap: 2,
});
wire.setAttribute('d', route.d); // концы на границах предметов
along(weight, route, { avoid: [leftCircle, rightCircle] });
```

`box(node, space)` измеряет преобразованный объект в координатах `space` (по
умолчанию корневой SVG). Для `beside` выбирай пространство родителя подписи.
`along` принимает `space` маршрута и сам переводит положение в пространство подписи;
`avoid` принимает измеряемые SVG-объекты и маршруты `{start, end}`. Передавай видимые
узлы, подписи и связи: размещение учитывает их границы и выбирает ближайшее свободное место.
`place` и `row` владеют `transform` размещаемого элемента. Для движения внутри
композиции добавь внутреннюю группу; так размещение и анимация не перезаписывают друг друга.
Соединение измеряй по контуру узла, отдельно от его внешних подписей.

## Состояние и движение

Для перехода на новый ввод останови прежнее движение его владельца:

```js
import { gsap } from '@visual-storytelling/core';
gsap.killTweensOf(pose);
gsap.to(pose, { x: target.x, y: target.y, duration: 0.35, overwrite: true, onUpdate: render });
```

В `Morph`, `MathMorph` и `InkMorph` передавай `render(frame, cues)`: политика движения и раскрытие результата принадлежат библиотеке. Для остальных предметных движений при ручном вводе reduced-motion сразу выставляет выбранную позу. В рассказе
сохраняй время смысловых событий; сокращай только декоративное движение через
`frame.reveal()`. Для непрерывных поз можно создать
`gsap.timeline({paused: true})`. В `shell.attachStory(...).render` вызывай
`animation.time(frame.time, false)`: рассказ задаёт время, GSAP рассчитывает позу.
Освобождай её через `shell.onDispose(() => animation.kill())`.
Метки слов, письмо и восстановление кадра описаны в [озвучке](narration.md#метки-и-js).
`write(text, p)` создаёт штрихи в соседней группе, оставляя исходный `<text>`
для измерения. Для общего скрытия или движения оберни надпись в `<g>` и меняй
эту группу. После изменения текста вызови `SketchMotion.resetText(text)` и
пересчитай размещение.
Для локальных подписей используй `place`/`beside`. Подпись главы `data-caption` по умолчанию
имеет `sr-only`: экранный диктор получает контекст, видимое объяснение живёт в рисунке.

## Видеокадр и действия

Для учебного ролика `SceneShell.mount(root, {frame: {width: 1280, height: 720, scope: 'scene'}})` создаёт единый кадр 16:9 с заголовком, выбором главы и нижним плеером. Оболочка масштабирует весь лист; `shell.stage` получает оставшуюся высоту в логических пикселях. Пояснения и ручные опыты сохраняют его границы. Открывай подробности внутри stage, как в `memory-register`; экспорт сохраняет эту композицию.

`frame.responsiveBelow: 904` позволяет тому же уроку перейти в обычный поток на узком экране; порог выбирают по читаемости уменьшенного текста. `SceneFrame` выставляет `data-frame-layout="responsive"` и сохраняет DOM, модель и часы; автор задаёт компактную предметную компоновку, как в `memory-register`. Выше порога возвращается исходный кадр, а короткое окно прокручивается по вертикали. Выпуск авторского кадра и видео всегда сохраняет фиксированные пропорции; HTML и PNG с текущими условиями сохраняют компоновку выбранного окна.

`scope: 'stage'` (значение по умолчанию) фиксирует только предметную область, например экран продуктовой инструкции; управление остаётся снаружи. `captions: true` включает субтитры поверх кадра. Для тихого рассказа `captions: {placement: 'below'}` оставляет текст под предметным кадром в читаемом экранном размере, как в `tesla-circuit`. При `scope: 'scene'` текст входит в общую композицию. Подписи и экспорт SRT/VTT используют одну дорожку речи или тихого сценария.

```js
import { storyActions } from '@visual-storytelling/core';
const actions = storyActions([
  { cue: 'enter_code', type: 'type', target: input, text: 'DEMO' },
  { cue: 'apply', type: 'press', target: button, result: confirmation },
]);
shell.onDispose(actions.dispose);
// В общем render(state, frame):
actions.render(frame);
```

Действия восстанавливаются при любой перемотке и регистрируют свои предметы в отчёте; для собственного действия `frame.target(cue, reviewId)` связывает метку с `data-review-id`. Проверка сравнивает этот предмет, исключая движение плеера и субтитров. Законченный пример — [продуктовая инструкция](../../../examples/product-walkthrough/scene.js).

## Показ и проверка

```sh
npm run pack                       # самодостаточный artifacts/story.html
npm run pack -- --inline            # компактная доставка для чата
npm run export -- --format mp4      # те же сцена и звуковая дорожка
```

Для полного выпуска: `npx visual-story deliver . --out artifacts/release --formats mp4,html,source`; после правки реплики повтори ту же команду. Она собирает озвучку с кэшем, рендерит видео частями и публикует выбранные файлы вместе; `--jobs` задаёт число работников. При необходимости добавь `srt,vtt` в форматы.

Обычный автономный HTML сжимает звук для доставки; `--audio original` сохраняет исходный формат. В Codex открывай проект через `story_open`; самостоятельный HTML доступен в браузере. `--inline` ограничивает размер отдельного вложения. Сохраняй атрибуцию звука. Примени [проверки формата](../SKILL.md#авторство-и-проверка) к конечной поверхности.

Сборка сохраняет вложенные папки ресурсов. Импортированные в JS изображения,
шрифты, аудио и GLB встраиваются как data URL; это подходит для автономного HTML.
Ресурсы, загружаемые произвольным `fetch(url)` или внешним сервисом, требуют
своего источника и сети. Проверяй итоговый файл офлайн. Производные отчёты храни
в `artifacts/`, чтобы следующая сборка не считала их исходниками.

Галерея навыка собирается из тех же исходников: в корне библиотеки `npm run build && npm run preview`. Превью пересоздаёт `npm run previews`; обновляй их после визуального просмотра.

Вложенные устройства и изменяемые симуляции: [камера, контуры и навигация](nested-explorer.md).
