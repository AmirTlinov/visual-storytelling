# Авторство через общий документ

Для готового механизма используй `story_create(document)`. Для собственной модели
добавь обычные JS/TS-модули через [manifest](document-modules.md): один `story.json`
определяет модель, представления, операции и главы. Создание открывает карточку;
правка обновляет существующий `root.scene`. Озвучка опциональна.

[Работающий шаблон](scene-template.md) и [эталон GPT](../../../examples/gpt-model/story-project.json)
проходят общий pipeline подготовки, проверки, истории, повторного открытия и выпуска.
Проверяй содержательную правку входа и эпизода, ручной опыт, обратный seek и один
плеер в узкой и широкой карточке. Сохраняй реальные значения и происхождение чисел.

`story_help(queries:["StoryModelModule","StorySubjectRecipe"])` раскрывает точные
типы установленного API. Адресная справка предпочтительнее чтения всего пакета.
CLI: `npx visual-story api NAME.member`, `api ./three`, `info`.

Новый предмет рисуется существующими средствами: `surface/lettering/svgButton`,
`Viewport3D`, `MathMorph`, `TensorData/Tensor3D`. Сценарное движение читает `frame`;
ручная камера подключается через `attachView`. Освобождай принадлежащие рисунку
ресурсы в `dispose`. Состояние времени, ввода, истории и доставки остаётся у оболочки.

Сложные постановки используют [пространственные главы](spatial-story.md),
[физический replay](physics-story.md), [тензоры](../../../docs/tensors.md) и
[математические превращения](../../../docs/morphing.md). Их предметная математика
сохраняется при подключении через общий документ; ручная оркестрация другого
плеера или копия общего lifecycle не требуется.

## Где что находится

[Карта владельцев](../../../docs/architecture.md) — источник границ библиотеки.
Авторский проект содержит `story-project.json`, `story.json`, model/drawing-модули
и ресурсы. Сборки, `timeline.json`, narration job и архив runtime — производные.
Пин проекта меняется явно через `story_migrate`; старые проекты сохраняют runtime.
