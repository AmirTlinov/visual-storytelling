# Опциональная озвучка

`story.json` хранит реплики, действия и зависимости речи от модели. Производное
задание `narration.json` создаёт `narrationSource`; его не редактируют и не хранят
как второй авторский сценарий. `timeline.json` хранит принятую запись и измеренные
акустические метки. Один Story/transport управляет временем и рисунком.

Начинай с тихого объяснения. Создание, правка, ручной опыт, Play, HTML/PNG/MP4
работают без голосовой модели. `story_voice(enabled: true)` явно выбирает
подготовку; `enabled: false` сохраняет выбранного провайдера и принятые записи.
Обычная правка исходника и preview не вызывают TTS/API. В `story_inspect`
поле `narration` перечисляет ready/pending целые мысли, число ожидающих единиц
и символов. Денежная стоимость остаётся неизвестной без тарифа провайдера.
Изменённая мысль молчит до явной `story_voice(enabled: true)`; подходящие принятые
мысли продолжают звучать. При смене структуры или непрозрачном
авторском модуле preview консервативно становится тихим. Сохранённая карточка
удерживает исходник принятой записи при GC. Финальный выпуск требует актуальной
проверенной записи либо явного `silent: true` / `--silent`.

## Мысль, действие и условия

Одна новая законченная мысль — один стабильный `beat.speech.id`. Без явного поля
нормализация создаёт `voice.chapter.beat` и фиксирует исходные входы моделей.
При включении голоса нормализованный документ сохраняется в проекте.
Для общей реплики задай `basis: "presented", models: []`; для числа укажи
только входы, от которых оно зависит:

```json
{
  "id": "notice",
  "say": "Соберём семнадцать предметов в группы по четыре.",
  "operation": { "model": "division", "name": "group" },
  "speech": {
    "id": "voice.lesson.notice",
    "when": {
      "basis": "presented",
      "models": [{ "model": "division", "inputs": { "count": 17, "divisor": 4 } }]
    }
  }
}
```

`basis: "authored"` консервативно ограничивает запись авторским режимом и
закреплёнными исходными входами. Это подходит для непрозрачной авторской логики.
`basis: "presented"` сравнивает условия с реально завершённым кадром модели.
Проверка не угадывает зависимости из текста: их задаёт автор.

Несколько соседних говорящих beats могут явно разделять один `speech.id`,
одинаковые `when`, `seed` и `delivery`: это один целый take с несколькими
действиями. Повтор ID через паузу или другую мысль запрещён. Новые самостоятельные
мысли получают разные IDs. ID нельзя переиспользовать для другого назначения.

Визуальное действие привязывай к своей фразе внутри мысли. Заверши группировку
до слов о получившихся группах; при словах об остатке выдели сам остаток.
Разделяй такие шаги на соседние beats с общим `speech.id`: запись остаётся целой,
а каждый шаг получает свои измеренные акустические границы. Не растягивай одно
действие на весь абзац. Проверь кадры перед произнесением результата и после него,
затем просмотри ролик целиком с нормальной скоростью и частотой от 30 fps.

При несовпадении условий замолкает весь неподходящий take. Возврат условий,
seek или снятие mute посреди мысли ждут начала следующей применимой мысли;
голос не включается случайным обрывком. Пользовательский mute независим от
применимости. У общей смешанной дорожки в неподходящем take отключаются голос
и музыка; в авторских промежутках музыка продолжается. Вторых часов музыки нет.

Короткие экранные пометки остаются возле предмета; `say` содержит естественную
связную реплику. Заголовок служит навигации. Пиши числа и формулы в произносимой
форме, а изображение оставляй математически точным. Выдели время увидеть исходное
состояние, преобразование и результат. `beat.timing` задаёт duration либо until
для действия; конфликт с принятыми акустическими границами останавливает сборку.

## Провайдер и кэш

По умолчанию при выборе озвучки используется локальный Higgs TTS 3 BF16 на
Apple MLX с принятым мужским образцом, seed 42 и пустым delivery. Пользователь
может выбрать свою локальную модель или API по [контракту адаптера](voice-adapter.md).
Системных голосов и автоматической подмены провайдера нет. `voice.json` хранит
только выбор; секреты API поступают из окружения.

Higgs: `document.narration.voice` задаёт `seed`, native `delivery`, либо пару
`reference_audio`/точный `reference_text`. Пути считаются от проекта.
`beat.speech.seed`/`delivery` меняют исполнение одной мысли. Адаптер использует
выбранные model/voice; Higgs seed/delivery и `music` ему не передают.

При явной подготовке после правки мысли content-addressed take/alignment caches
переиспользуют остальные записи. Изменение рисунка, камеры, условий, пауз или
музыки пересчитывает только нужные метки/монтаж/мастеринг при подготовке. Вызов синтеза относится
к изменённому исполнению, а не к главе. Принятую речь не режут на слова ради кэша.
Higgs может подготовить длинную мысль из целых предложений; авторская единица,
её IDs и целые принятые границы сохраняются.

Явная миграция старого проекта связывает прежние whole takes с соседними beats,
сохраняет WAV, границы, seed, reference и delivery без синтеза. Правка внутри
такого take пересоздаёт весь take. Непринятый независимый `narration.json` требует
явного переноса замысла в документ; миграция не выбрасывает его текст.

## Подготовка и проверка

Плагин подготавливает Python, Higgs, aligner и FFmpeg через общую отменяемую
очередь. Первое включение требует около 12 ГБ загрузок, 18 ГБ свободного места;
рекомендуется 32 ГБ памяти. Готовность `doctor` проверяется без загрузки моделей.
Кэш моделей находится в `~/.cache/sketch-visualization` (`SKETCH_AUDIO_CACHE`),
интерпретатор плагина — в его постоянном каталоге окружения.

В проекте `visual-story audio .` явно подготавливает голос из документа и выбора
`voice.json`; `visual-story build . --no-audio` сохраняет тихий путь.
Низкоуровневые `sketch-audio build/check/audition` работают с производным заданием
существующего аудиовладельца. Для сравнения интонации используй целые дубли и
запиши выбранный seed в `beat.speech.seed`, затем подготовь запись.

Higgs выпускает `audio.wav`, `voice.wav`, при музыке `music.wav`, `timeline.json`
и `voice-preview.html`. WAV имеют общий ноль и длительность. Проверка source,
reference, stems и аудиобайтов выполняется до публикации. Ошибка/отмена сохраняют
прежний принятый выпуск. Мастеринг целится в −16 LUFS с потолком −1.5 dBTP;
короткая запись без измеримого LUFS использует RMS −20 dBFS. Интонация и
sample-позиции сохраняются. Тихая исходная речь не меняет баланс ducking музыки.

Проверь короткую, длинную и тихую мысль, вопрос, начало и хвост, переход к соседней
мысли; затем прослушай полный MP4. Измеренные слова и громкость не доказывают
качество интонации. Проверяй N=17→18 посреди зависимой мысли, generic реплику,
pause/seek/restore/mute и ошибку провайдера. TTS/API при этих действиях — 0.

## Выпуск

`story_produce` выбирает authored build либо `conditions: "current"` с показанным
build/session. HTML/PNG/SVG/MP4 сохраняют выбранные условия, IDs и checkpoint;
MP4 воспроизводит выбранный story/interval при зафиксированных экспериментальных
входах. Take, который не помещается в интервал целиком, исключается вместе с музыкой
в его границах. Неприменимая мысль исключается целиком из общей дорожки. Тихий MP4 не
содержит аудиотрек. Новая озвучка эксперимента требует отдельной авторской правки
реплик/условий и явной подготовки выбранным провайдером.

После прерванной подготовки используй `story_retry` исходного job: он восстановит
публикацию проверенных аудиофайлов до нового обращения к модели. Обычный preview и
проверка экспорта восстановление не запускают. При изменённых захваченных исходниках
повтор завершится ошибкой; не удаляй recording receipt и не запускай новый синтез
для обхода ошибки.
