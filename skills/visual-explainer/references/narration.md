# Озвучка, музыка и единое время

Реплики и смысловые метки находятся в `narration.json`; время, плеер и рисунок
используют общий `timeline.json`.

## Выбор голоса

Для авторской озвучки по умолчанию используется нейросетевой Higgs TTS 3.
`story_voice` показывает готовность провайдеров и сохраняет выбор в `voice.json`
одной отменяемой правкой. Выключение и повторное включение сохраняют провайдер,
голос и язык; правка реплики переиспользует неизменённые фрагменты.
`voice.json.enabled` — единственное сохранённое включение голоса. Тихий проект
сохраняет `story.json` или `narration.json`; обычная правка и выпуск его не включают.
`story_produce` выпускает результат с выбранной озвучкой.

```json
{ "provider": "higgs", "enabled": true, "language": "ru-RU" }
```

В плагине инструмент, образец голоса и закреплённые описания зависимостей уже входят в комплект. `story_voice` подготавливает Python, модели и FFmpeg через общую очередь. До запуска сообщи требования: около 12 ГБ загрузок, 18 ГБ свободного места, рекомендуются 32 ГБ памяти. Пользователь может отменить подготовку и продолжить её с проверенных частей. Музыка подготавливается при использовании.

Голоса macOS, включая Milena, выбирай по явной просьбе пользователя:
`story_voice` с `provider: "macos"` либо такой же провайдер в `voice.json`.
Системный синтез поддерживает `music: null`. Для тихого черновика используй `--no-audio`.

## Локальный Higgs

Модели закреплены в `tools/audio/models.json`, Python-зависимости — в `tools/uv.lock`.
Модели и кэш хранятся в `~/.cache/sketch-visualization` (`SKETCH_AUDIO_CACHE`).
Плагин устанавливает Python в свой постоянный каталог окружения. `doctor` читает готовность без загрузок.

Для отдельного CLI из каталога навыка:

```sh
../../tools/sketch-audio doctor
../../tools/sketch-audio setup
../../tools/sketch-audio build narration.json --out ./audio
../../tools/sketch-audio check narration.json --timeline ./audio/timeline.json
node ../../tools/scene.mjs preview ./audio
```

CLI setup использует `uv`; в плагине установкой инструментов владеет `environment`, ручная настройка PATH не нужна. `SKETCH_AUDIO_BIN` — явный внешний провайдер, `SKETCH_AUDIO_PYTHON` — подготовленный интерпретатор. Встроенный мужской образец находится в `dist/assets/audio/narrator-male.wav`. Генерация и выравнивание идут локально.

Для прослушивания открой `/voice-preview.html` на выданном адресе. Готовую сцену запускай той же командой `preview`, передав каталог сборки.

Для рассказа с рисунком до синтеза свяжи реплики с действиями по
[визуальной раскадровке](visual-storytelling.md). В каждой ключевой фразе
должно быть время увидеть исходное состояние, преобразование и его результат.
Подгоняй реплику и паузы под объясняемое действие. Если при сборке обнаружился
смысловой разрыв, вернись к сцене и пересобери затронутую фразу.

Минимальный сценарий для озвучки — одна мысль одним дублем; для рисунка добавь
`cues`, как в [рабочем примере](../../../examples/explorer-svg/narration.json):

```json
{
  "version": 3,
  "segments": [
    {
      "id": "question",
      "text": "Три пары — сколько это предметов? Попробуй посчитать.",
      "pause_after": 2
    }
  ]
}
```

Поля сценария:

- `version: 3`, `intro`, `outro` — секунды до/после речи.
- `voice`: `seed` (42), `delivery` (по умолчанию пустая строка: манера принятого
  энергичного мужского образца без дополнительного усиления эмоций). Для своего тембра задай
  `reference_audio` и его точный `reference_text`; путь считается от `narration.json`
  или исходного `story.json` и сохраняется при переносе каталога сцены.
- `segments`: смысловые фразы с уникальным `id`, `text`, коротким `title` для заголовка и выбора главы (по желанию), необязательными
  `delivery`, `seed`, `pause_after` и `cues`. Сегмент содержит связную законченную мысль,
  несколько действий рисунка получают свои `cues` внутри него. Длинный сегмент
  автоматически собирается из законченных предложений примерно по 40 слов:
  `id`, метки и общая нумерация слов сохраняются. Предложение длиннее 50 слов
  нужно разделить по смыслу. Каждая часть проходит акустическую проверку;
  исчерпавший бюджет синтеза дубль не попадает в кэш. Внутренние паузы создаёт модель,
  между частями оставляется не менее 0,2 с с учётом уже записанной тишины.
  `pause_after` по умолчанию равен нулю. Дополнительную паузу задавай для
  конкретного действия, самостоятельного предположения или смысловой остановки.
- `delivery` сегмента заменяет общую подачу; пустая строка оставляет её образцу.
  Выбирай одну устойчивую манеру реплики; вопрос, приглашение и вывод сначала вырази
  естественным текстом и пунктуацией, сохраняя характер рассказчика.
  В `text` допустимы [штатные теги Higgs](https://huggingface.co/bosonai/higgs-tts-3-4b/blob/main/PROMPTING.md),
  например `<|style:whispering|>` или `<|emotion:surprise|>`.
  Они исключаются из субтитров и выравнивания. Эмоциональные теги — грубое управление
  подачей: не рассчитывай на точный сброс интонации внутри дубля; паузы ставь в нужном месте.
- Числа, формулы и латинские сокращения пиши произносимыми русскими словами;
  на рисунке остаётся любая математическая запись. Используй `ё`, где она нужна.
  Используй обычную орфографию без специальных знаков ударения.
- Если нужны субтитры с другой записью произнесённого, задай, например, `"captionAliases": {"пэ дэ эф": "PDF"}` на уровне сценария; экран и SRT/VTT используют общую замену и время всей фразы.
- `captionTrack` собирает слова в читаемые реплики: короткий хвост переносится вместе с соседними словами, паузы сохраняются, текст занимает до двух строк. По умолчанию — до 76 знаков, 42 знака в строке и 5 секунд; целевое минимальное время показа — 0,8 секунды, ограниченное следующим словом или главой. Эти пределы задаются через `maxChars`, `lineChars`, `maxSeconds`, `minSeconds`.
- `cues: [{"id":"answer", "quote":"двадцать три", "action":"Под группами появляется общее количество 23"}]` создаёт именованный
  интервал по словам. Для повторяющейся цитаты добавь `occurrence: 2`.
  ID сегментов и меток составляют одно пространство имён:
  строчная латинская буква, затем строчные буквы, цифры, `_`, `.` или `-`
  (`[a-z][a-z0-9_.-]*`), например `count_tiles`.
  Каждой авторской метке дай `action` (что видно до, во время и после действия)
  либо `hold` (что зритель читает, сравнивает или предсказывает). Глагол привязывай
  к операции над предметами. Метки сегментов служат навигации по главам.
- Если действие длится дольше цитаты, добавь `"timing":{"duration":9,"delay":0.2}`:
  начало — через 0,2 секунды после начала цитаты, длительность — 9 секунд.
  Вместо `duration` можно задать `"until":"next_action"`: конец совпадёт с началом
  исходной речевой метки `next_action`, независимо от её собственного `timing`.
  Окно должно быть положительным и помещаться в дорожку; для финального действия
  оставь `pause_after` или `outro`. Длительность и задержка задаются в секундах.
  В `story.json` это то же поле `timing` у beat: `until` принимает ID следующего
  beat своей главы или полный `chapter.beat`. `documentNarration` сохраняет его при
  проекции в речь. Без озвучки длительность действия выделяет место в общей шкале;
  с готовой речью действие может занимать оставленную паузу, сохраняя слова и звук.
- `music: null` отключает музыку. Пример: `{"track":"inspired","offset":32,
"level_db":-19}`. Для другой композиции: `path`, `offset`, `level_db` и
  `credit` с `title`, `artist`, `source`, `license`, при наличии `license_url`.
  Относительный путь считается от сценария. Название трека не задаёт настроение
  всем будущим роликам: выбирай музыку по конкретному материалу.

Результат: `audio.wav` (готовая общая дорожка), `voice.wav`, при музыке
`music.wav` (уже приглушённый фон), `CREDITS.txt`, `narration.txt`, `timeline.json`
и страница прослушивания `voice-preview.html`.
Сцена импортирует `timeline.json`; сборщик включает его в итоговый JS.
Все WAV начинаются в общей точке ноль и имеют одинаковую длительность.
`source_sha256` связывает метки с точным сценарием; звук и `timeline.json`
обновляются одной сборкой. Сборка сцены с активной сгенерированной озвучкой проверяет
эту связь и содержимое выбранных файлов голоса и музыки через ту же установку
`sketch-audio` (штатная проверка использует стандартную библиотеку Python без загрузки моделей); при их изменении сначала
выполни `npm run audio`. `dev` и `deliver` подготавливают изменённую озвучку сами.
Тихие сцены проверки не требуют.
Музыка тише голоса, автоматически приглушается во время речи и плавно входит/выходит.
Визуализация воспроизводит `audio.wav`; стемы оставлены для редактирования.

Повторная сборка переиспользует неизменённые голосовые фрагменты и их метки.
Правки музыки, вводной паузы и пауз между фрагментами пересчитывают монтаж
без повторного синтеза. Файлы сцены в выходном каталоге не изменяются.

Для неудачной интонации сравни цельные дубли одной мысли штатной командой:

```sh
sketch-audio audition narration.json --segment question --out artifacts/voice
node ../../tools/scene.mjs preview artifacts/voice
```

`index.html` содержит три варианта; `--seeds 42 43` задаёт свои. Выбранный `seed` запиши
в этот сегмент сценария и пересобери аудио: выбранный дубль и неизменённые реплики
берутся из кэша, все метки пересчитываются вместе со звуком. Проверяй начало, вопрос, приглашение, вывод и переход
к соседней реплике; уверенность выравнивания не оценивает интонацию.
Дорабатывай текст, общий голосовой образец или целый дубль; склейка отдельных фраз
из разных исполнений меняет манеру и не служит настройкой рассказчика.

Создание сцены с зависимостями и упаковка для чата описаны в
[справке сцены](scene-authoring.md).
Preview поддерживает byte-range запросы для перемотки WAV; обычный HTTP-сервер
может оставить аудио без доступной перемотки.

## Метки и JS

В `timeline.json` все `start`/`end` уже относятся к итоговой дорожке:

- `segments[]`: `id`, `text`, `start`, `end`, `audio_start`, `audio_end`,
  `seed`, `delivery`, `words[]` с текстом, временем и акустическим `score`.
- `cues[id]`: `text`, акустические `start`/`end`, авторские `action`/`hold` и необязательное
  `timing` — сегменты и цитаты. Изменение `timing` обновляет метки с прежними голосовыми дублями.
- `duration`, имена аудиофайлов, сведения о сборке, музыке и `warnings`.

Подключи метки в `shell.attachStory` из [авторского шаблона](scene-template.md):

```js
const controller = shell.attachStory({
  audio,
  script: timing,
  stateAt: () => ({ answer: result }),
  render(state, frame) {
    answer.text(state.answer);
    answer.write(frame.reveal('answer'));
    SketchMotion.draw(underline, frame.reveal('answer'));
  },
});
controller.seek(timing.cues.answer.start);
```

`cueSheet(script)` разрешает `timing` один раз: `frame.cue(id)`, `progress`, `reveal`,
`has`, `finished` и отчёт используют окно действия; `cue.speech` сохраняет исходный
акустический интервал. `sheet.script` содержит разрешённые метки. Текст и `segments[].words`
остаются прежними. При наличии задержки переходи к действию через `controller.sheet.get(id).start`.
`frame.elapsed(id)` возвращает секунды от начала действия, начиная с нуля; прогресс и elapsed
попадают в наблюдения кадра. Для морфов передавай `render(frame, id)`: физическая длительность
берётся из того же окна. При reduced motion `progress` и `elapsed` сохраняют время,
а `reveal` сразу показывает элемент в начале действия; морфы сохраняют своё время раскрытия результата.

Оболочка подключает плеер, главы, `root.scene` для экспорта и общий `dispose`.
Название главы формулирует текущий вопрос. Итог, подпись и формула получают собственные
метки: показ абзаца целиком в начале главы может выдать следующий вывод раньше голоса.

Каждый кадр вычисляй как `render(audio.currentTime)`: показываемые элементы,
камера, штрихи и значения должны восстанавливаться при перемотке. Таймеры,
цепочки `setTimeout` и отдельные часы анимации создают рассинхронизацию.
Для интерактивного изменения исходных данных заново собери соответствующий
сценарий или явно переключи режим; прежняя озвучка относится к своему примеру.
Выключение звука глушит всю дорожку, сохраняя ход анимации и выбор звука при повторе.

`write` рисует упорядоченные штрихи букв из `src/ink/glyphs.ts`: кириллица,
латиница, цифры и основные знаки. `writeSequence([elements], p)` пишет ряд
последовательно внутри одного смыслового действия. Для отдельно произносимых
размеров, слагаемых, знаков и ответа используй отдельные `cues` и `write`:

```js
write(heightLabel, frame.reveal('height_value')); // «четыре сантиметра»
write(widthLabel, frame.reveal('width_value')); // «пять сантиметров»
write(productSign, frame.reveal('multiply_sign')); // «умножить на»
write(resultLabel, frame.reveal('product_result')); // «двадцать»
```

Метка абзаца подходит для навигации по главам. Вывод нового факта начинается
на его словах и заканчивается к концу соответствующей реплики; паузы сохраняются.
Разбиение общей длительности по длине надписей не учитывает речь.
Действие над несколькими предметами можно распределить внутри метки своего
глагола: например, добавить три ряда за «добавим ещё три таких ряда».
`render` получает `Frame` текущего аудиовремени: `progress(id)` — ход операции, `has(id)` — начало, `finished(id)` — завершение;
`reveal(id)` сокращает декоративное рисование при reduced motion. При копировании
значение получателя меняется по `finished`, даже если движение отключено:

```js
transferDrawing.render(frame.progress('copy'), frame.reduced);
receiver.set(frame.finished('copy') ? sourceValue : previousValue);
```

Для изменяющихся величин вычисляй все зависимые числа из текущего входа.
В reduced-motion сохраняй время получения результата и порядок фактов.

`draw(path,p)` рисует отдельный штрих, `trace([paths],p)` —
несколько по очереди, например стержень и наконечник стрелки. Разделяй пути
в местах отрыва пера (`M`); кончик штриха перемещается по его геометрии.
Если нужен отсутствующий символ, добавь осевые штрихи либо оставь его статичным.
После изменения текста/переноса вызови `resetText` и пересчитай композицию.

## Речь и музыка

Higgs TTS 3 — основной локальный генератор русской речи. Сохраняй принятый
мужской тембр, живую заинтересованность и естественный темп. Разнообразие интонаций
следует смыслу фраз; задумчивость не означает замедление всего рассказа. Эмоции задаются штатными средствами модели;
ускорение и изменение высоты готовой записи в сборке отсутствуют.
Исходные параметры: BF16, `temperature: 0.8`, `top_k: 50`, `seed: 42`.
Время для рисунка обеспечивай формулировкой и смысловыми границами рассказа.
Для смены рассказчика используй чистую запись на русском и точную расшифровку.

Выбирай негромкую инструментальную музыку без конкурирующего вокала и резких
переходов; настроение следует теме. У свободного трека сохрани источник,
лицензию и атрибуцию в `CREDITS.txt`; подпись под роликом не нужна.
Пример Inspired — Kevin MacLeod,
[источник](https://incompetech.com/music/royalty-free/index.html?isrc=USUAN1600022),
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

## Проверка

После сборки сцены получи кадры на границах и внутри авторских меток:

```sh
visual-story review dist --out review
visual-story review dist --out review-narrow --cue copy --width 375 --theme dark --reduced
```

Открой `review/index.html`: карта всех глав связывает реплики, операции и кадры.
`--cue` выбирает действие целиком с контекстом до/после; плеер отчёта показывает
сохранённые кадры и доступное аудио. Это обзор состояний по перемотке; ритм
реального воспроизведения проверяется записью. `session.json` хранит индекс,
`capture/frames.json` — кадры, снимки модели и фактически прочитанные метки.
[Инспектор сеанса](motion.md#проверка) открывает нужный момент или объект без
повторного захвата; `--out` создаёт подробный отчёт из сохранённых данных.
`SceneShell.attachStory` публикует единый `SceneHandle` в `root.scene`; дополнительные ресурсы регистрируй через `shell.onDispose`, предметный снимок задавай в `root.scene.snapshot`. При самостоятельной разметке источник отчёта — `controller.review`.
Инструменты вызывают методы сцены; общий плеер и native SVG служат адаптерами
для примеров без собственного `seek`. Статичной сцене фиктивная перемотка не нужна.
Обращения к `frame.progress/has/finished/reveal` учитываются в отчёте.

Отчёт отмечает непрочитанные или неописанные метки, одинаковые кадры действия,
нехватку места у подписей и предупреждения рендера. Полный отчёт отдельно показывает
реплики с интервалами от секунды без `action/hold`: сверь их кадры со словами,
особенно первый видимый вывод. Такой интервал может быть уместной паузой; решает просмотр. `hold` допускает неподвижность. Обращение к метке само по себе не доказывает
правильность показа: сопоставь видимое действие с репликой, проверь промежуточные
равенства и происхождение результата. Отчёт дополняет полный просмотр со звуком
и проверку перемотки; смена камеры или подписи может скрывать неподвижный механизм.
Метки получены CTC-выравниванием:
это акустические оценки с шагом около 20 ms, не гарантированные фонетические
границы. Посмотри `warnings` и контрольные акценты: скопление неуверенных слов у
конца записи может означать пропуск речи, поэтому сверь её с текстом и пересобери
затронутую реплику более короткими смысловыми фрагментами.
Отсутствующую речь нельзя исправить растягиванием меток по длительности.

Бэкэнд: [Higgs TTS 3 BF16](https://huggingface.co/bosonai/higgs-tts-3-4b)
через MLX Audio на GPU Apple Silicon;
[русский Wav2Vec2](https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-russian)
создаёт метки. Ревизии обеих моделей закреплены в `../../tools/audio/resources.py`.
Выравниватель использует MPS, когда доступен; `--device cpu` меняет только его устройство.
`timeline.json` сохраняет модель, ревизию, версию MLX Audio и хеш образца голоса.

бесплатные авторские ролики, в том числе монетизированные, с заметной атрибуцией
в записи или сопровождающем тексте. Встраивание модели в продукт требует
отдельной лицензии; условия находятся в карточке модели.
