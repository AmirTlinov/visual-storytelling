# Выбранная локальная модель или API

По умолчанию проект использует Higgs TTS 3 BF16. Для другой модели агент создаёт
один адаптер внутри проекта и сохраняет выбор через `story_voice`. Адаптер
принадлежит конкретному сервису: одинаковое название «TTS API» ещё не означает
совместимость форматов, голосов и меток.

## Подключение

1. Используй уже выбранные пользователем сервис, модель и голос. Уточни только
   недостающий выбор. Прочитай официальную документацию именно этого провайдера:
   запуск модели или endpoint, формат WAV/PCM и реальные временные метки.
2. Создай `voice/adapter.mjs` через `story_edit`. Для локальной модели адаптер
   вызывает её подготовленный процесс или локальный сервис; для API — его endpoint.
   Зависимости и веса готовь в соответствии с выбранной моделью. Они не входят
   автоматически в комплект Higgs.
3. Сохрани настройку через `story_voice` с `context` из предыдущего результата
   и новым `requestId`. Пример сохраняемого `voice.json`:

   ```json
   {
     "provider": "api",
     "enabled": false,
     "model": "eleven_multilingual_v2",
     "adapter": "voice/adapter.mjs",
     "voice": "CHOSEN_VOICE_ID",
     "language": "ru-RU"
   }
   ```

   Для локальной модели укажи `provider: "local"`, её `model` и адаптер. `voice`
   необязателен, если модель не требует отдельного идентификатора рассказчика.
   Эти поля сохраняются при отключении и повторном включении озвучки.

4. Ключ передавай через окружение запуска процесса плагина. В проекте и коде
   хранится только имя переменной, например `ELEVENLABS_API_KEY`. Не помещай
   значение в `voice.json`, исходники, аргументы команды, сообщения или логи.
   Уже запущенный runtime не наследует новые переменные терминала: после настройки
   окружения перезапусти его штатным способом. Проверяй наличие ключа без печати.
5. `story_voice` без включения показывает статическую готовность. Обычная правка
   озвученного проекта сохраняет ready takes и помечает изменённые pending без
   запуска адаптера. Перед явной подготовкой прочитай `narration.preparation`
   из `story_inspect`: количество единиц и символов; денежный тариф задаётся отдельно.
   Финальный выпуск с pending требует подготовки либо явного тихого варианта.
   `readiness: "adapter-configured"` и `synthesisVerified: false` означают лишь
   корректную конфигурацию и доступный файл. Запусти одну короткую реплику выбранным
   провайдером по контракту ниже, прослушай запись и сравни метки с произнесёнными
   словами. Затем включи выбранный голос через `story_voice(enabled: true)` и
   проверь cue сцены, отмену и повтор подготовки. Запрос API может расходовать
   средства; используй разрешённый пользователем сервис и объём.

Общий маршрут работает на Mac и Linux; запуск конкретной локальной модели зависит
от её требований. Системного голоса и автоматического переключения на другой
провайдер нет. Для адаптера пока используй `music: null`.

Общую дорожку мастерит FFmpeg, который плагин подготавливает для обоих providers.
Измерение LUFS и true peak задаёт один постоянный gain: цель −16 LUFS, потолок
−1.5 dBTP. Ограничение пиком может оставить запись тише цели; динамика, голос и
временные метки сохраняются. Моно измеряется как dual mono. Для слишком короткого
звука без измеримого LUFS используется опора RMS −20 dBFS с тем же потолком пика.
Метод, измерения, ограничение пиком и версия профиля входят в служебный receipt.

Смена профиля ремастерит принятый `audio.wav` локально, без нового запроса
провайдеру, даже если кэш отдельных takes уже отсутствует. Текущие профиль и
контрольная сумма дают повторную подготовку без FFmpeg и изменения файлов.
Повреждённая принятая запись завершается ошибкой; платный повтор не подставляется
вместо восстановления. Исходные `take.wav` в кэше остаются неизменными.

## Контракт процесса

Плагин запускает поставляемый Node с файлом адаптера без shell. `adapter` — путь
к `.mjs` внутри проекта. Собственный код адаптера, его helpers и конфигурацию
храни в одной папке, например `voice/`: их содержимое определяет актуальность
кэша. Endpoint и версию модели зафиксируй в этой конфигурации или поле `model`;
окружение используй для ключей и расположения кэша. Веса модели храни отдельно
от `voice/`, указывая проверяемую версию. Импорты за пределами папки адаптера
не входят в его контрольную сумму. Параметры образца и речевые теги Higgs для
local/API удаляй из сценария: они отклоняются до обращения к провайдеру.

Один запуск получает одну реплику JSON через stdin:

```json
{
  "version": 1,
  "provider": "api",
  "text": "Добавим ещё один ряд.",
  "model": "eleven_multilingual_v2",
  "voice": "CHOSEN_VOICE_ID",
  "language": "ru-RU",
  "outputDirectory": "/absolute/temporary/take"
}
```

Адаптер записывает обычный файл `take.wav` в выданный `outputDirectory`: WAV,
PCM signed 16-bit little-endian, один канал, 8–192 кГц. Частота соответствует
реальному звуку и одинакова у всех реплик. Затем он
возвращает в stdout единственный JSON:

```json
{
  "words": [
    { "text": "Добавим", "start": 0.12, "end": 0.55 },
    { "text": "ещё один ряд.", "start": 0.58, "end": 1.42 }
  ],
  "alignment": { "method": "provider-word-timestamps" }
}
```

Время дано в секундах от начала `take.wav`. Положительные конечные интервалы
покрывают весь текст в порядке произнесения, не перекрываются и помещаются в файл.
Допустимы слова или группы слов с
действительными границами группы; короткую цитату внутри такой группы нельзя
считать точно размеченной. `alignment.method` — короткий идентификатор реального
метода: латинская строчная буква, затем строчные буквы, цифры, `_`, `.` или `-`,
всего до 80 знаков. Выходной JSON ограничен 1 МБ. Итоговая сборка создаёт
`audio.wav` и `timeline.json`; адаптеру не нужно собирать общую дорожку.

Если API не возвращает метки, адаптер выполняет акустическое выравнивание
готового звука с текстом. Запрещено подставлять равные интервалы, оценки по числу
букв или общей длительности. Неполная речь, несовпадающий текст и непригодная
разметка завершают дубль ошибкой. Подробности диагностики допустимы в stderr
без ключей, заголовков авторизации и приватного текста; не печатай их в stdout.
Отмена должна прекращать запрос и дочерние процессы. Автоматический повтор
платного запроса после неоднозначной сетевой ошибки не выполняй.

## Готовый пример ElevenLabs

Скопируй [elevenlabs-voice-adapter.mjs](elevenlabs-voice-adapter.mjs) в
`voice/adapter.mjs` проекта. Он использует только встроенные модули Node и
`ELEVENLABS_API_KEY`. Модель и голос поступают из `voice.json`; пример выше
показывает `eleven_multilingual_v2`, отдельный голос выбирает пользователь.

Пример вызывает официальный [Create speech with timing](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)
с `output_format=pcm_24000`, оборачивает PCM в WAV и объединяет исходные символьные
границы из `alignment` в слова. Он проверяет полное совпадение текста, времён
и длины записи. `normalized_alignment` не подставляется вместо исходного текста:
при другой нормализации сначала исправь произносимую запись или добавь проверенное
акустическое выравнивание. Формат PCM S16LE описан в
[документации синтеза](https://elevenlabs.io/docs/overview/capabilities/text-to-speech#supported-output-formats).

У `eleven_multilingual_v2` язык определяется текстом; API не поддерживает для
этой модели `language_code`. Для других моделей пример передаёт языковую часть
`ru-RU` как `ru`. Совместимость выбранного языка и модели проверь у провайдера.
Код не делает платных повторов и скрывает тело ответа при ошибке.

Тест с подставленным transport подтверждает запрос, формат WAV и преобразование
меток. Реальное соединение, качество голоса и условия аккаунта проверяются
коротким синтезом после подключения пользователем своего API.

Адаптер в корне проекта владеет только своим entry, буквальными локальными imports и ресурсами `new URL("...", import.meta.url)`. Авторский `story.json`, рисунок и камера не входят в его identity. Для динамических импортов или npm-зависимостей используй отдельную папку адаптера. Явная миграция переносит прежний root fingerprint и проверенные take caches без нового запроса; удалённый кэш не блокирует перенос WAV. Неизменённый whole take восстанавливается из принятой записи и её измеренных меток без TTS; мастеринг остаётся общим.
